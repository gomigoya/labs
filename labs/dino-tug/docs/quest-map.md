# 공룡과 줄다리기 — 퀘스트 지도

[이론 카드](theory-card.md)의 식과 문법을 따른다. 완료 조건은 `PHYS.judgeQ1`~`judgeQ7`만 계산한다. 종은 SPECIES의 한국어 키, 바닥은 GROUNDS의 μ를 순수 값으로 전달한다. 이름은 코드와 문서에만 있고 화면은 입체 견본·모양·마디·점·색으로 구성한다.

교육과정 원문(`science-2022.csv`, UTF-8 BOM):

- **4과01-01**: “일상생활에서 힘과 관련된 현상에 흥미를 갖고, 물체를 밀거나 당길 때 나타나는 현상을 관찰할 수 있다.”
- **6과01-03**: “화석의 생성 과정을 모형으로 설명하고, 지구의 과거 생물과 환경을 추리하는 활동을 통해 화석의 가치를 인식할 수 있다.”

모든 퀘스트는 4과01-01에 직접 연결한다. 6과01-03은 화석에 근거한 과거 생물 추리와 **추정 모형의 한계**를 다루는 보조 연결이다. 근육 법칙을 실제 공룡의 측정 결과라고 평가하지 않으며 화석 생성 과정은 별도 수업이 필요하다.

모든 수 입력 판정은 정수 1~100명, 명세의 종과 바닥 견본만 허용한다. Q2·Q3의 고정 종·바닥 조건도 함수가 검사한다. Q1·Q7은 정확한 정수 칸 전체가 허용 구간이다. 레일 칸 폭은 각각 **0.01**로 요구 **0.009** 이상이며 양끝 칸도 같다. DETENTS는 **1·10·20·30·49·59·68·100**, 최소 간격 **0.09**로 요구 **0.05** 이상이다. 함수와 역매핑은 이론 카드 f에 정의한다.

## 원리 카드 — 글 없는 그림 등식

| # | 그림 등식 제작 설명 |
|---|---|
| 1 | 주황 한 마디와 초록의 더 짧은 실선 비교 → 주황 방향 깃발. 초록 보라 윤곽보다 분홍 윤곽이 안쪽 |
| 2 | 같은 주황 조각 더미를 이어 붙임 → 초록 윤곽을 막 넘어서는 끝 |
| 3 | 거대 표본의 체중 덩어리와 더 작은 근육 윤곽을 분리 → 말뚝 더미의 합이 그 윤곽을 초과 |
| 4 | 같은 말뚝 더미·같은 표본 + 두 바닥 견본 → 서로 반대인 깃발 방향 |

## 퀘스트 진행 규칙과 측정 경계

- 예상 고르기 전에는 대상 조작을 잠그고 카드가 흔들리는 피드백을 준다. 선택 뒤 이번 손잡이 하나가 빛난다. 나머지는 은은하게 남겨 자유 탐구로 이어진다.
- 예상 → 조작 → 관찰 사건 → 예상과 실제 겹침 → 원리 카드 순서다. 예상이 틀려도 감점하거나 완료를 막지 않는다. 모델 결과와 다름을 보고 다시 생각할 수 있다.
- 이번 조건은 완료 후 유지하고, 다음 퀘스트 진입 시에만 시작 조건을 세운다. Q4는 Q3의 성공한 팀을 복사하고 Q5는 유리 조건을 이어 받는다. Q7만 30명·자갈로 고정한다. 정적 관계이므로 지속 시간 조건을 새로 추가하지 않는다.
- UI가 당김을 실행할 때마다 증가하는 양의 정수 `run`을 부여한다. 기록은 `{run,n,species,mu}`이며 결과는 저장된 winner 문자열을 신뢰하지 않고 PHYS.outcome으로 재계산한다. 완료된 실행만 observations에 넣는다. 드래그 중 샘플·후보 미리보기는 실행 기록이 아니다.
- Q4는 서로 다른 실행에서 같은 인원·종의 두 바닥을 비교한다. 배열의 시간 순서는 무관하다. Q5는 `after.run > before.run`으로 시간 순서를 확인한다. run은 실행 식별자이며 PHYS는 전역 카운터를 소유하지 않는다. 같은 run은 재실행 증거가 될 수 없다. 퀘스트 재진입 시 관찰 배열·방문 목록을 새로 비운다.
- 데이터가 없으면 observations·visited는 빈 배열, before·after는 null이다. 미관찰 상태를 0 N의 측정으로 그리지 않는다. 판정은 false이며 `slipOnset`의 이전 힘이 없으면 null이다.
- `slipOnset`은 정확한 마찰 한계 도달이 아니라 직전 이하에서 현재 초과로 넘어갈 때만 true다. 한계 사건은 연출 쿨다운보다 먼저 기록한다. 한계 계산에 무한한 값이나 가짜 운동 궤적을 넣지 않는다. 최소 인원의 Infinity는 계산 상한 내 해 없음 사건으로 바꾼다.
- 정적 승부에서 패배가 근육 제한이면 미끄러짐을 연출하지 않는다. 마찰 제한이면 발 접촉과 미끄러짐 방향을 상징으로 보여 준다. 깃발 이동과 회색 시간 점은 **추정 연출**, 실제 가속도 검증에 쓰지 않는다.
- Q6의 compareOpen과 visited는 실제 비교 창 열기·종 선택 이벤트로 UI가 만든 순수 플래그다. 같은 종을 여러 번 선택해도 다른 종 방문으로 세지 않는다. 새 렌즈가 열리면 이전 렌즈를 닫는다.
- 단어 없이 진행점·채운 카드 슬롯·기구 선화로만 진행을 표시한다. 도구 설명과 성취기준은 화면 밖 교사 안내서에 둔다. 모든 시각 숫자는 본 문서의 설명이며 기본 화면은 마디·점·모양만으로 읽힌다.

## 구현 분할

이번 단계는 M1과 두 설계 문서만 생성한다. 아래는 다음 단계의 경계다.

| 단위 | 책임 | 완료 기준 |
|---|---|---|
| M1 물리 | PHYS·hand-check | 명세 수치·독립 손계산, 판정 통과·실패·경계, 전체 종·바닥·인원의 반환값 검증 |
| M2 방·콘솔·모형 | 표본실·트랙·카세트·입체 견본·레일 | PHYS.SPECIES·GROUNDS·RANGE·DETENTS 사용. 질량에서 공룡 실제 키를 발명하지 않음. 가로·세로 장치 전체와 셸 여백 확보 |
| M3 시각 문법·셰이더 | 마디·두 한계·접촉 렌즈·두 그래프·입자 | PHYS의 한계와 forceVisual 사용. 압축 구간에 끊김·⤢, 색과 선 모양 이중 부호. 저사양에서도 한계·그래프 유지 |
| M4 퀘스트·연출 | 후보 루프·기록·판정·카드·진행점 | judgeQ1~Q7에 순수 값 전달. 실행 번호·빈 상태·순간 사건 보존. Q4 동일 조건 비교, Q5 증가량, Q6 실제 열람 기록 재현 |

확인 명령은 `node tools/hand-check.mjs`, `node --check src/15-physics.js`, `node --check tools/hand-check.mjs`다. PHYS 로드는 마커 사이를 new Function으로 실행한다. 화면·렌더·성능 검수는 M2 이후의 책임이며 이번 물리 검증 통과가 화면 검수 통과를 뜻하지 않는다.
