# 원리와 시각 문법 — 로켓 발사대

학생·자유·교사 화면의 기본 표현은 코드 기하·선화뿐입니다. 글·수식은 이 문서와 안내서에서 읽습니다. 선택 수치 층만 숫자·허용 단위를 씁니다.

| 실제 층 키 | 원리 → 표현 | 선택 이유 |
|---|---|---|
| `마디` | 추력·무게·지지력을 같은 힘 마디의 화살표로 비교 | 한 마디는 엔진 하나의 6900000 N. 빈 마디·채운 마디·빗금으로 색 외에도 구별합니다. |
| `상쇄·쌓아 채우기` | 겹친 힘을 상쇄하고 받침에서 부족분을 채움 | 불꽃만으로 이륙하지 않음을 설명합니다. 별도 잉여 화살표 중복은 숨기고 큰 쌍의 남은 부분을 봅니다. |
| `문턱` | 점선 무게 문턱과 마주 보는 촉 | 즉시 이륙의 엄격 부등식과 받침 틈을 연결합니다. |
| `계단` | 노즐 개수에 따른 같은 높이씩 증가하는 마디 | 정수 1~5개의 조작 범위와 일치합니다. Q2 사건에서는 중복 기둥을 숨기고 추력·무게 쌍에 집중합니다. |
| `겹치기·숨은 구조` | 탱크 단면, 이전 연료·무게, 지구·달 비교 | 질량 감소와 중력 변화의 원인을 구별합니다. |
| `시간·운동` | 같은 시간 간격 위치 점과 별도 선형 점 띠 | 속력과 가속도 변화를 고도 압축에서 분리합니다. 범위 초과는 끊김 도형입니다. |
| `기록` | 노즐·짐·천체 조건과 결과 막대의 현재/고정 비교 | 무엇을 바꾸고 유지했는지 남깁니다. 빈 기록에 결과 영을 만들어 넣지 않습니다. |
| `그래프` | 힘·속도 곡선, 현재 점, 속도 접선 | 같은 양의 색을 장치와 일치시킵니다. 콘솔 기본 곡선은 항상 유지하고 이 층은 장치 위 비교 곡선·접선을 제어합니다. |

장면 층 키는 `room`, `console`, `hero`, `rocket`, `fuel`입니다. 교사 전체 층 순서는 `console → hero → rocket → fuel` 다음 위 표 순서입니다. 방 `room`은 배경이라 쌓기에서 제외합니다. 장면 층을 끄면 자식도 가려지는 관계를 유지합니다.

추력 보라 `#b594ff`·빈 마디, 무게 주황 `#ffaa63`·채운 마디·아래 촉, 지지력 분홍 `#f28db8`·빗금·위 촉, 속도 청록 `#64ead0`입니다. 실선·밝은 점은 현재/관찰, 점선은 기준/예측, 회색 점은 과거입니다. 점선 콘솔 전체 곡선은 현재 조건의 PHYS 예측이며 아직 관찰하지 않은 자료를 측정으로 표시하지 않습니다. 소진 추력 점프는 분리합니다. A/B 고정은 `GRAMMAR.pin()`의 세계 좌표 윤곽이며 카메라를 바꾸어도 같은 장치와 비교합니다.

후보는 같은 받침·힘 눈금·점 띠를 씁니다. Q1은 큰 틈/작은 틈/받침 위, Q2·Q6은 굵은 노즐 묶음 개수, Q3은 넓게 펼친 같은 눈금의 시간 점 간격, Q4는 짐과 남는 마디/노즐 추가/받침, Q5는 천체와 노즐 개수로 구별합니다. 잘못된 후보는 오개념 가설 도해이며 물리 기록이 아닙니다. 사건 해설은 한 개만 표시하고 빈 SVG·말풍선은 만들지 않습니다.

가로 히어로는 장치 60~75%를 목표로 투영 탐색하고 예상 카드를 오른쪽 별도 띠에 둡니다. 세로는 아래 후보 띠를 예약합니다. 콘솔까지 이중 맞춤하던 후퇴를 제거했습니다. Q2 사건은 탱크·노즐 샷으로 짧게 접근해 높이 기둥 옆 이륙을 봅니다. 로켓과 불꽃은 기존 표현 배율을 유지하고 노즐 중심 간격을 넓혔습니다. 바닥은 프레임에서 줄이는 방법을 택했습니다.

쓰지 않은 표현: 실제 사진·삽화·이모지·문자 눈금·회전 궤도 시뮬레이션·실제 화염 온도색·압축된 높이 간격으로 속력 재기. 설명이 물리 모델의 범위를 넘거나 화면을 읽는 데 글을 요구하기 때문입니다. 배경 궤도 패널은 소품이며 계산 결과가 아닙니다.

브라우저 없는 검증은 후보 SVG 유한성·물리 경로·층 키·금지 API를 확인했습니다. 5초 판독, 장치 가림, 색 대비와 투사 거리 판독은 캡처 호스트에서 확인해야 합니다.
