# 로켓은 언제 땅에서 떠오를까 — 이론 카드 (설계서 1/2)

슬러그: `rocket-liftoff`. 대상: 초등 3~6학년. 명세 `D:/labs/topics/specs/rocket-liftoff.md`가 기준이며, 연결 퀘스트는 [quest-map.md](quest-map.md)에 둔다.
참고: `master-lab-prompt.md` 0·1·2·3·5장, `site-addendum.md`, `moon-closer`의 문서 구조.
이 문서는 이론 해부 a~q를 채운다. 이번 산출물은 순수 물리와 검증·설계이며 화면 코드는 포함하지 않는다.

## a. 한 줄 통찰

로켓은 추력이 무게를 넘어야 뜬다. 같은 추력이라도 연료가 줄어 가벼워지면 가속도가 커진다.
추력과 무게가 같다는 말은 그 순간의 가속도가 영이라는 뜻이다. 연료가 계속 타면 바로 뒤에는 무게가 줄어 평형이 깨진다.

## b. 3단계 학습 경로

| 단계 | 알아낼 것 |
|---|---|
| 알아챌 현상 | 불꽃이 있어도 엔진이 부족하면 발사대에 남는다. |
| 조작하며 발견할 규칙 | 엔진을 늘리면 위쪽 힘 마디가 늘고, 짐을 늘리면 아래쪽 힘 마디가 늘어난다. 달에서는 아래쪽 마디가 짧다. |
| 비교로 확인할 법칙 | 추력과 무게를 상쇄한 나머지가 운동을 바꾼다. 연료가 줄면 같은 추력의 나머지가 커져 같은 시간의 이동 점이 더 빠르게 벌어진다. |

## c. 보이지 않는 주인공과 시각 형태

주인공은 **추력·무게·발사대 지지력의 관계**다. 셋 모두 같은 힘 눈금을 쓴다.

- 추력은 위쪽 보라 실선 화살표, 무게는 아래쪽 주황 실선 화살표, 지지력은 발사대에서 올라오는 분홍 화살표다.
- 색각 차이에도 읽히도록 추력에는 빈 마디, 무게에는 채운 마디, 지지력에는 빗금 마디를 쓴다.
- 공통 힘 한 마디는 엔진 하나의 추력인 6.9e6 N이다. 화살표 길이는 `stateAt`의 `T`, `W`, `normal`을 `C.engineThrust`로 나눈 값이다.
- 겹치는 마디를 상쇄하고 남는 위쪽 마디만 강조한다. 땅에서는 지지력이 부족분을 채워 결과가 영임을 보여 준다.
- 연료 탱크 단면은 남은 연료 `(m - C.mDry - load) / C.mProp`만큼 채운다. 이전 무게는 점선 윤곽으로 남긴다.
- 같은 시간의 위치 점은 `simulate`의 `h`에서 취한다. 점 간격은 속력, 점 간격이 변하는 정도는 가속도의 증거다.

## d. 영웅 장치와 방

우주센터 관제 모형실의 콘솔 위에 **로켓 발사대 모형** 하나를 둔다. 원통·원뿔·핀으로 구성한 로우폴리 입체, 분해 가능한 노즐 묶음, 연료 단면, 짐 결합 홈, 옆 높이 기둥이 장치다.
벽·바닥·창틀·선반이 공간을 만들고 창밖에는 낮 하늘이 보인다. 발사 지도와 궤도 도식은 글 없는 선화다. 실제 궤도 비행을 계산한다는 인상을 주지 않도록 궤도 패널은 배경 소품으로만 둔다.

## e. 지배 방정식 (실제 PHYS와 동일)

단위는 kg, m, s, N, m/s²이다. 상수는 모두 `PHYS.C`에 있다.
건조 질량 970000 kg, 고정 연료 2000000 kg, 엔진 하나 추력 6900000 N, 유효 배기 속도 2580 m/s, 지구 중력 9.81 m/s², 달 중력 1.62 m/s², 기본 표본 간격 0.01 s다.

1. **질량과 연소**: `m0(load) = C.mDry + load + C.mProp`, `Tn = n*C.engineThrust`, `q = Tn/C.ve`, `tb = C.mProp/q`. 소진 전 `m = m0 - q*t`, 이후 `m = C.mDry + load`. `T = Tn`은 `t < tb`에서만 성립하고 소진 순간부터 영이다. 짐은 항상 건조 질량에 더한다.
2. **문턱과 받침**: `W = m*g`. 발사대에서는 `normal = max(0, W-T)`, `a = 0`. 비행에서는 `normal = 0`, `a = T/m-g`. `Tn/(C.mDry+load) <= g`면 끝까지 못 뜨므로 `liftoffTime = Infinity`. 그 외 `L = max(0, (m0-Tn/g)/q)`다. `enginesNeeded = floor(m0*g/C.engineThrust)+1`이므로 힘이 정확히 같으면 엔진을 더 요구한다. 최소 개수가 조작 범위를 넘더라도 계산값을 잘라 거짓 성공을 만들지 않는다.
3. **연소 중 운동의 정확 적분**: 이륙 질량 `ml = m0-q*L`, 이륙 뒤 연소 경과 `u = min(t,tb)-L`, `mu = ml-q*u`에 대해 `v = ve*ln(ml/mu)-g*u`, `h = ve*(u-mu/q*ln(ml/mu))-g*u²/2`. 이륙 전에는 위치·속도·가속도가 영이다. `simulate`는 이 적분을 기본 0.01 s 고정 격자에 표본화한다. 이륙을 다음 프레임까지 늦추는 오일러 적분 오차가 없다. 짧은 구간의 로그에는 `log1p`를 쓴다.
4. **소진 뒤 운동**: 소진 상태를 `hb,vb`로 두면 `s=t-tb`, `h=hb+vb*s-g*s²/2`, `v=vb-g*s`, `a=-g`. 착지 시각은 `tb+(vb+sqrt(vb²+2*g*hb))/g`. 이후 `h=v=a=0`, `normal=W`. 착지는 완전 비탄성으로 멈춘다고 두는 **추정**이며 반발은 계산하지 않는다.
5. **로켓 방정식 대조**: 즉시 이륙하는 기본 짐·엔진 5개에서 이상 속도 증가 `ve*ln(m0/mEnd)=2887.074594 m/s`, 소진 시각 `149.5652174 s`, 중력 손실 `g*tb=1467.234783 m/s`, 순속도 `1419.839811 m/s`. 명세의 2890·1423 m/s와 허용오차 안에서 같다. 지연 이륙의 속도 적분은 점화 질량 대신 이륙 질량에서 시작한다. 발사대에 있던 동안의 중력 손실을 비행 속도에서 또 빼지 않는다.

### API·측정 경계

명세 공개 API `C, m0, thrust, T0W, liftoffTime, enginesNeeded, simulate, judgeQ1…judgeQ6`를 그대로 제공한다.
추가 API는 `burnTime`, `stateAt`, `RANGE`, `DETENTS`, 레일 정·역매핑, `heightVis`, `flameVis`다.
`stateAt(n,load,g,t)`는 `{t,h,v,a,m,T,W,normal,onPad,landingT}`를 반환한다. 스칼라 계산 함수는 유효한 SI 입력을 전제로 하며 검증을 중복하지 않는다.
`simulate(n,load,g,tEnd,dt=C.dt)`의 반환은 `{t:[],h:[],v:[],a:[],m:[],liftoffT,events:[]}`다. 마지막 시간이 격자 사이면 끝점 하나를 덧붙인다. 사용자 지정 `dt`는 표본 간격만 바꾸며 물리식은 바꾸지 않는다.

- 입력 경계: 엔진은 정수이며 조작 범위 안, 짐은 유한한 비음수, 중력·dt는 유한한 양수, 종료 시간은 유한한 비음수여야 한다. 무효·누락 종료 시간은 빈 배열과 `liftoffT:null`을 돌려준다. 시간 영은 초기 표본이 있는 유효 측정이다.
- 유효 실행의 불가능한 이륙은 `Infinity`다. 무한대나 아직 일어나지 않은 사건을 그래프 점으로 만들지 않는다. `events`에는 관측 종료까지 발생한 `liftoff`, `burnout`, `landing`의 정확한 시각만 담는다.
- 이륙 시각은 엄격 부등식이 성립하기 시작하는 경계의 하한이다. 그 순간 힘이 같으면 `onPad:true`, 직후에는 비행이다. 즉시 추력이 더 크면 점화 시각부터 `onPad:false`다. 연료 소진과 문턱이 겹치면 이륙 사건이 없다.
- PHYS에는 실행 번호나 기록을 저장하지 않는다. 호출자가 새 실행마다 증가시키는 양의 정수 `runId`를 준다. 조건을 바꾸면 새 실행이며 열람 플래그도 해당 실행에만 속한다. 판정에는 물리 결과를 조작한 값 대신 입력 조건·관찰 시각·UI 열람 플래그만 준다.

## f. 조작 변수 (장면 속 손잡이)

| 변수 | 손잡이·범위 | 걸림·매핑 |
|---|---|---|
| 엔진 수 | 노즐 묶음 손잡이 또는 더하기·빼기 도형, 정수 1~5개 | `engineRailX=(n-1)/4`; x=0,0.25,0.5,0.75,1. 역매핑은 가까운 정수 칸으로 걸린다. |
| 추가 짐 | 도구대의 빈 홈·중간 블록·큰 블록 3칸 | 0,200000,500000 kg. `loadRailX`는 x=0,0.5,1. 질량 연속 슬라이더가 아니다. |
| 천체 | 표면 무늬가 다른 지구 구와 달 구의 2칸 | 9.81,1.62 m/s². `gRailX`는 지구 x=0, 달 x=1. |

연료는 가득 고정이고 조작 변수가 아니다. 시간은 재생·일시정지·사건 건너뛰기로 관찰하며 새 슬라이더 범위를 만들지 않는다.
레일은 모두 범주 수가 작아 선형이면 충분하다. `RANGE`는 양 끝, `DETENTS`는 유효 선택 전체다. 걸림 간 최소 간격은 엔진 0.25, 짐 0.5, 천체 1이다.
최근접 선택의 끝 칸도 엔진 x 폭 0.125, 짐 0.25, 천체 0.5다. 각각 요구 폭 0.009와 간격 0.05를 넘는다. 물리 판정에 임의의 실수 허용 구간을 추가하지 않는다.

## g. 원리 → 시각 문법 대응표

| 원리 | 3장 사전의 표현 | 화면에 표시 |
|---|---|---|
| 힘 크기 | 마디 | 같은 눈금의 보라·주황·분홍 화살표 |
| 합력 | 상쇄·쌓아 채우기 | 보라와 주황의 겹친 마디 소거, 발사대의 분홍 부족분 채우기 |
| 이륙 조건 | 문턱 | 받침 윤곽 위에서 떨어져 나오는 로켓, 마주 보는 화살촉 |
| 엔진 수와 추력 | 계단 | 노즐 개수에 맞춰 같은 길이씩 늘어나는 보라 마디 |
| 연료 감소·짐 비교 | 겹치기·숨은 구조 | 이전 무게 점선과 줄어든 실선, 탱크 단면, 짐 결합 홈 |
| 속력·가속도 | 시간·운동 | 같은 시간의 위치 점, 커지는 점 간격과 회색 잔상 |
| 반복 비교 | 기록 | 시행 조건을 나타내는 구·블록·노즐 도형과 결과 막대, 달라진 조건의 테두리 |
| 관찰 곡선 | 그래프 | 양의 색 곡선과 현재 점, 글 없는 격자와 축 끝 도형 |

실선·발광은 지금, 점선은 기준, 회색 잔상은 과거다. 같은 양의 색·무늬를 화살표와 그래프에서 유지한다.

## h. 퀘스트

6개: 엔진 하나의 연료 끝까지 → 즉시 뜨는 개수 → 연료와 가속도 → 짐 비교 → 달 비교 → 무거운 짐의 최소 엔진 설계.
학습 질문·행동·증거·판정 입력은 [quest-map.md](quest-map.md)의 표가 기준이다. 화면 연출이나 예상 정답 선택 자체가 완료를 대신하지 않는다.

## i. 예상 그림 후보와 오개념

같은 로켓 모형의 짧은 루프 또는 선화 도해를 후보로 쓴다. 불꽃만 있으면 천천히라도 뜬다는 오개념, 같은 추력은 같은 가속도라는 오개념을 반드시 포함한다.
실제 모델과 모순되는 후보는 의도적인 오개념 도해이며 실험 결과로 기록하지 않는다. 후보·정답 표는 퀘스트 지도에 둔다.

## j. 원리 카드

노즐·짐 블록·천체 구·화살표 마디·시간 점을 잇는 글 없는 그림 등식이다. 수식·단위·문장을 화면에 적지 않는다. 각 퀘스트의 등식은 퀘스트 지도에 둔다.

## k. 콘솔 그래프 2개

1. **힘–시간**: 가로축 끝은 원형 시계 도형, 세로축 끝은 마디 화살표다. 추력 보라·무게 주황·지지력 분홍을 같은 축에 그린다. 이륙·소진은 사건 핀, 과거 시행은 점선, 현재 시각은 밝은 점이다. 소진 불연속은 수직 연결선 대신 전·후 끝점을 구분한다.
2. **속도–시간**: 가로축은 같은 시계 도형, 세로축은 간격이 벌어지는 점 묶음이다. 속도 곡선은 밝은 청록으로 두고, 가속도 열람 시 현재 접선의 기울기를 겹친다. 속도는 청록 점·곡선으로 통일한다. 하강의 음수 속도는 아래쪽 반면으로 나타낸다.

축 눈금은 마디·점·격자만 쓴다. 고도는 옆 기둥과 운동 점으로 관찰한다. 데이터가 없으면 빈 격자이며 영인 측정선과 구별한다. 무한대 대신 연료가 빈 탱크와 발사대에 남은 로켓을 그린다.

## l. 현상 셰이더 설계

- 노즐마다 반투명 보라 불꽃과 하향 스트릭을 둔다. 총 불꽃 길이 단위 합은 `flameVis(T)=T/C.engineThrust`; 가동 노즐마다 나누면 각 노즐은 한 단위다. 소진 뒤에는 영이다. 압력·온도·실제 불꽃 색 계산이라는 뜻은 아니다.
- 힘 화살표 셰이더는 같은 마디 주기, 실선·점선 스타일, 무늬와 화살촉을 지원한다. 정규화한 `T`, `W`, `normal`을 입력하고 장면에서 힘을 새로 정하지 않는다.
- 탱크 단면의 반투명 매질은 연료 비율로 높이가 내려간다. 소진율에 비례하는 흐름 스트릭은 아래쪽 노즐로 향한다. 입자 밝기는 총 추력 비율, 힘의 정체성은 보라색으로 읽힌다.
- 블룸은 발광 현상에만 제한한다. 저사양에서도 단면·힘 마디·곡선은 유지하며 입자 밀도만 줄인다. 난수 물리나 화면 프레임에 종속된 판정은 쓰지 않는다.

## m. 교사 시연 순서 (향후 guide용)

| 순서 | 발문 | 켤 층과 A/B 비교 |
|---|---|---|
| Q1 | 불꽃이 있으면 언제나 뜰까? | 힘 마디 → 받침 힘 → 탱크 단면. 가득 찬 때와 연료 끝을 겹친다. |
| Q2 | 기다리지 않고 뜨는 노즐 묶음은? | 엔진 계단 → 문턱. 기본 짐에서 엔진 4개·5개의 점화 순간을 고정 비교한 뒤, 4개도 기다리면 뜨는 사건으로 잇는다. |
| Q3 | 같은 힘인데 점 간격은 왜 더 빨리 벌어질까? | 탱크 단면 → 무게 잔상 → 속도 접선. 같은 시행의 처음과 연소 중간을 비교한다. |
| Q4 | 짐이 커지면 꼭 엔진을 더 달아야 할까? | 중간 블록·큰 블록 비교 → 무게 마디 → 남는 추력. 같은 엔진 묶음에서 점화 상태를 비교한다. |
| Q5 | 달에서도 같은 노즐 묶음이 필요할까? | 지구·달 구 → 주황 무게 → 이륙 문턱. 같은 짐·엔진 하나를 비교한다. |
| Q6 | 무거운 짐을 즉시 띄우는 가장 작은 묶음은? | 목표 짐 윤곽 → 엔진 계단 → 결과 상쇄만 남긴다. 엔진 4개·5개의 점화를 비교한다. |

교사 발문은 문서에서만 읽는다. 시연 중에도 화면에는 단어·단위·수식이 없다.

## n. 흔한 오해 2개와 깨는 장면

1. “엔진 하나라도 켜면 천천히 뜬다.” → Q1에서 탱크가 비어도 로켓이 받침 위에 남는다. 연료가 더 많아도 소진 질량은 그대로이므로 해결되지 않는다. 반면 Q2의 엔진 4개는 가벼워지면 뒤늦게 뜬다.
2. “추력이 일정하면 가속도도 일정하다.” → Q3에서 보라 마디는 고정, 주황 마디는 줄어든다. 속도 그래프의 접선이 더 가팔라지고 운동 점 간격의 증가폭도 커진다.

## o. 과장 스케일 목록 (화면에는 ⤢ 도형)

| 항목 | PHYS와 대응 | 정직한 해석 |
|---|---|---|
| 고도 압축 ⤢ | `heightVis(h)=ln(1+max(0,h)/1000)/ln(2)`; 0 m→0, 1000 m→1 모형 단위 | **추정**: 압축 기준 1000 m는 전시 설계값. 실제 고도·속도는 압축하지 않은 배열로 기록한다. 압축 좌표의 점 간격은 속력을 직접 비교하기 어려우므로 운동 점은 고정 선형 배율의 별도 시간 점 띠에도 둔다. |
| 불꽃 길이 ⤢ | `flameVis(T)=max(0,T)/6900000` | 추력의 선형 도해이고 실제 배기 불꽃 길이 예측이 아니다. |
| 로켓·발사대·노즐·천체 구 ⤢ | 모형 형상 | 실제 크기 비율·지구와 달 사이 거리를 나타내지 않는다. 힘 화살표는 서로 같은 눈금을 유지한다. |

### 근사와 한계·결정 기록

- 수직 단일 단계, 일정 추력·배기 속도·중력, 공기저항 없음. 고도에 따른 중력 감소, 진공 추력 변화, 단 분리, 자세·궤도는 계산하지 않는다. 지구와 달 선택은 중력만 바꾼다.
- 질량·추력·배기 속도는 새턴 V 첫 단을 연상시키는 교육용 단순화이며 실제 기체 재현이 아니다.
- **추정**: 착지는 반발 없이 멈춘다. 실제 착륙 장치·충격·파손은 다루지 않는다. 이 가정은 코드와 문서에 함께 표시한다.
- 짐 이름의 모순: 명세의 열거대로 빈 홈=추가 0, 중간 블록=추가 200000, 큰 블록=추가 500000 kg로 확정한다. 기본 실행은 수치 요구사항대로 추가 0이다. Q4의 ‘보통→무거움’은 중간 블록→큰 블록으로 판정한다. 화면에는 이 이름을 적지 않는다.
- 명세의 ‘연료가 더 많았다면 엔진 하나도 결국 뜰 수 있다’는 오류다. 엔진 하나 추력 6900000 N < 건조 무게 9515700 N이므로, 연료량만 늘려도 어느 순간에도 무게를 이길 수 없다.
- `simulate`는 고정 격자에서 해석적 정확 적분을 사용한다. 근사 수치 적분 대신 이 방식을 택해 지연 이륙·소진 사이에 생기는 스텝 의존 오차를 제거했다. 별도 사건 배열이 경계의 시각을 보존한다.
