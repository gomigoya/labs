## 퀘스트 연결표

판정의 공통 기록은 `r={runId,n,load,g,t}`다. `runId`는 새 실행마다 증가하는 양의 정수, `t`는 그 실행의 점화 뒤 관찰 시각이다.
`ignited`, `accelerationSeen`, `comparisonSeen`은 해당 실행·비교에 속한 UI 플래그다. UI는 계산된 가속도나 임의의 성공값을 전달하지 않는다.

Q1·Q2·Q5·Q6의 한 행동은 점화, Q3은 연소 관찰, Q4는 한 조건 비교다. Q4의 두 기록은 점화 순간의 `T0W`를 비교하므로 `t`가 달라도 비교 기준은 처음 질량으로 고정한다.
Q2·Q5·Q6의 즉시 이륙은 나중의 관측 시각이 아니라 점화 순간 비율로 판정한다. ‘지금 떠 있음’을 ‘즉시 떴음’으로 바꾸지 않는다.

## 퀘스트 진행 규칙

- 장면 제시 → 예상 후보 선택 → 조작 → 관찰 → 예상과 실제 비교 → 원리 카드 순서다. 예상 전 장치가 잠기고 선택 후보의 윤곽만 강조한다. 틀린 예상은 감점하지 않고 두 도해를 나란히 남겨 다시 보게 한다.
- 진행 지도는 장치 도형과 채워지는 점, 현재 단계의 빛으로만 표시한다. 자유 실험에서는 모든 선택이 열리며 퀘스트 중에도 나머지 손잡이는 은은히 남는다.
- 현재 완료 직후에는 조건을 유지한다. 다음 퀘스트에 진입할 때만 해당 시작 조건을 세운다. Q1·Q2·Q3은 기본 짐·지구, Q4는 엔진 5개·중간 짐·지구, Q5는 기본 짐·달·엔진 하나, Q6은 큰 짐·지구로 시작한다.
- 점화 뒤 엔진·짐·천체를 바꾸면 종전 궤적을 소급 수정하지 않는다. 새 조건의 준비 상태가 되고, 다음 점화에 새 실행 번호를 부여한다. Q4는 두 준비 상태를 고정 기록할 때에도 서로 다른 증가 번호를 준다. PHYS는 실행 번호를 만들거나 보관하지 않는다.
- Q1은 연료 끝까지 확인해야 한다. 긴 대기는 소진 사건으로 이동하는 기하 도형 버튼으로 건너뛸 수 있다. 실제 물리 시각은 소진까지 이동하며 연료 소진 전 성공을 주지 않는다. 기록 시각은 애니메이션 프레임 수가 아니다.
- Q3의 가속도 열람 플래그는 해당 실행의 초기 접선과 연소 중 접선을 함께 본 뒤 켠다. Q4 비교 플래그는 두 기록을 실제로 연 뒤 켠다. 재점화·조건 변경 시 이전 열람 플래그를 재사용하지 않는다.
- `runId`가 영·음수·정수가 아니거나, 조작 범위를 벗어난 조건·없는 시각·없는 기록이면 판정은 실패다. 중복 실행 번호와 역순 실행 번호로 Q4를 완료할 수 없다.
- 과거 기록은 조건 도형과 결과 막대로 표시한다. 같은 시각 비교와 시간 경과 비교를 구별한다. 초기 기록이 없으면 곡선·비교 막대를 임의의 영 값으로 만들지 않고 빈 칸으로 둔다.
- `Infinity`는 사건도 위치 점도 아니다. 이륙·소진·착지의 유한 시각만 사건 핀으로 남기며 곡선의 불연속을 직선으로 메우지 않는다. 도중에 멈춘 실행은 아직 도달하지 않은 사건을 완료로 세지 않는다.

후속 구현도 판정·식·수치는 PHYS에만 둔다. 이 단계에서는 위 향후 파일을 만들지 않는다.

## 명세 대조·결정 기록

- 기본 짐의 이름과 값이 충돌하므로 수치 요구사항을 우선했다. Q4의 보통은 중간 블록으로 해석하고 초기 기본 실행과 구분한다.
- ‘연료가 더 많으면 엔진 하나도 결국 뜬다’는 설명은 버린다. 소진 뒤 건조 무게는 9515700 N으로 엔진 하나의 6900000 N보다 크다. 연료 증량은 소진 질량을 낮추지 못한다.
- 명세의 이상 속도 2890·순속도 1423 m/s는 반올림 근사다. 실제 식의 2887.074594·1419.839811 m/s가 각각 요구 오차 안이므로 상수를 바꿀 이유가 없다. 큰 짐 비율도 1.013493으로 명세의 1.0134와 요구 오차 안이다.
- `liftoffTime=0`과 ‘그 순간 힘이 같음’은 구별한다. 경계 시각은 하한, 즉시 이륙 판정은 엄격한 `T0W>1`이다. 단지 시간이 영이라는 이유로 성공을 주지 않는다.
- **추정**은 고도 압축 기준과 착지의 비반발 가정이다. 값과 식은 이론 카드·PHYS에 명시했다. 실제 로켓의 비행 예측으로 일반화하지 않는다.
