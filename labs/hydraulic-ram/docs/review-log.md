# 비평 로그 — 수격펌프

캡처는 `node tools/capture.mjs`(Playwright, 1440×900 · 375×812, 14개 상태)로 만들고 `shots/rN/`에 둔다. 각 라운드의 `report.json`에 상태별 콘솔 에러 수와 가로 스크롤 여부가 있다.
점수는 "냉정한 아트 디렉터" 기준 1~10점이다.

## 라운드 0 — 히어로 구도 (shots/r0-hero*.jpg)

- 추정 구도(정면 대각)에서는 장치가 작고 콘솔 화면이 HUD 패널 밑에 깔렸다.
- 투영 탐색(`__lab.searchHero`)을 바꿨다. 높이를 제곱근으로 압축하고, 콘솔 화면 3개를 비교 대상으로 넣고, "화면이 0.4W 오른쪽" 조건을 추가했다.
- 결과: fov 34, 방위각 6°, 고도 25°, 거리 4.6, 면적 0.65, 잘림 2.

## 라운드 1 — HUD 포함 첫 캡처 (shots/r1)

| 가장 나쁜 문제 | 조치 |
|---|---|
| 모바일: 공급 탱크와 라벨이 왼쪽 가장자리에서 잘림 | 세로 히어로 재조정 (0.9, 3.1, 6.6) → (−0.45, 1.55, −0.2). 라벨 x를 화면 안으로 당김 |

| 모바일 SLOW-MO 태그가 두 줄로 꺾임 | `white-space: nowrap` |

## 라운드 2 — 전체 세트 (shots/r2, 28장, 에러 0, 가로 스크롤 0)

| 가장 나쁜 문제 | 조치 |
|---|---|
| 무거운 밸브(멈춤)인데 자막이 "한 박자에 0.000 L가 버려집니다"(가속 단계 문장) | noclose 멈춤이면 위상과 상관없이 정지 자막 |
| 극단(H4 h5 m0.1)에서 수두선이 톱니처럼 떨림 | 수격 순간 밖에서 시간 평활 τ = 40 ms (시뮬 시간) |
| 분해 근접 샷에서 물보라 점이 눈송이만 해짐. 콘솔 화면에 흰 사각 반사 | 점 크기 상한 0.004·uScale. 화면 유리 거칠기 0.04 → 0.3 |

추가: 근접 투어 샷에서 "공급 탱크" 라벨이 헤드라인 위로 겹침 → HUD 블록과 겹치는 라벨 숨김. 모바일 투어에서 근접 샷을 쓰지 않게 함.

## 라운드 3 — (shots/r3, 28장, 에러 0, 가로 스크롤 0)

| 가장 나쁜 문제 | 조치 |
|---|---|
| 관 근접 샷에서 수두선이 노드마다 번갈아 뛰는 톱니(MOC 격자 나이퀴스트 모드가 제곱근 눈금 0 근처에서 커 보임) | 수격 순간 밖에서 [1,2,1] 공간 필터. 제곱근 눈금을 완화형으로 바꾸는 안은 H = 1 m에서 탱크 바닥이 책상을 뚫어 기각 |

| 캡처 스크립트가 이전 상태 변수를 끌고 감(투어 캡처가 극단 상태로 찍힘) | 상태마다 프리셋 1로 초기화 |

## 라운드 4 — 최종 세트 (shots/r4, 28장, 에러 0, 가로 스크롤 0) + 성능

성능 측정(GTX 1060, Chromium D3D11, 1440×900, 고품질 고정):

| 항목 | 프레임 |
|---|---|
| 전부 켬 (시작) | 31.6 ms |
| GTAO 끔 | −5 ms |
| 보케 끔 | −4 ms |
| 그림자 끔 | −2 ms |
| 투과 유리 1종 끔 | −5 ms |

조치: 투과 유리를 반사·클리어코트 유리로 교체, 그림자 맵은 3프레임마다(조작 중에는 매 프레임) 갱신, GTAO 샘플 12 → 8, 자동 하향 임계 32 → 25 ms.
결과 **1440×900 21.1 ms(47 fps), 375×812 17.1 ms(58 fps)**, 모두 고품질. 약한 GPU는 25 ms를 넘으면 AO → 픽셀 비율 → 보케 순으로 자동으로 내린다.

r5(hero·explode·preset-high)로 유리와 수두선을 다시 확인했다.

## 라운드 5 — 사이트 빌드 통합 (dist, shots/dist)

| 문제 | 조치 |
|---|---|
| 셸 API가 `window.__SITE__`에만 있고 문서의 `window.__site`가 없음 | 별칭 추가 |
| 1180 px 미만에서 셸 알약(왼쪽 아래)과 조작 힌트 바(하단 중앙)가 겹침 | 1180 px 미만에서 힌트 바 숨김(조작법은 도움말에 있음) |
| 모바일에서 셸이 "HYDRAULIC RAM" 머리글을 가림 | 셸은 좁은 화면에서 짧은 이름(←·공유·저사양), 의뢰 버튼은 숨김. 실험실은 모바일에서 영문 머리글 생략 |
| 공유 버튼이 두 개(실험실 + 셸) | 사이트 빌드에서는 실험실 쪽 공유 버튼 숨김 |
| 빌드가 `src/`·`tools/`까지 배포 폴더에 복사 | 빌드 제외 목록에 추가(dist 374 KB) |

## 시각 판정 체크리스트 (최종 히어로, 1440×900)

- [x] 장치가 화면의 60% 이상 — 투영 면적 0.65
- [x] 프레임에서 잘리는 물체 2개 이상 — 잘림 2(선반, 플로어 램프 쪽 벽)
- [x] 보이는 실용 광원 4개 이상 — 펜던트, 플로어 램프, 선반 LED, 콘솔 램프·화면
- [x] 따뜻한/차가운 보색 대비
- [x] 배경에 흐린 소품 5개 이상, 검은 허공 없음 — 선반 소품, 화분, 라디에이터, 창, 벽 도표 3
- [x] 단색으로 빈 큰 면 없음 — 벽지·징두리판·커팅 매트 격자
- [x] 콘솔 화면에 움직이는 그래프 — 밸브 쪽 압력, 양수량 곡선
- [x] 다이얼 원호가 값과 일치 — H, h 다이얼(ARC 1.25π, 1.5π 쓸기)
- [x] 현상이 전용 셰이더로 빛나고 흐름 입자가 있다
- [x] 헤드라인이 동사형 훅 — "물이 솟는다"
- [x] 캡션에 실제 숫자 2개 이상 — "0.658 L를 6 m 위로 … 3.0배"
- [x] 라벨·패널·텍스트 겹침 없음 — HUD와 겹치는 라벨 숨김
- [x] 모바일에서 장치 전체가 보인다
- [x] 비교 대상 3개(콘솔 화면 2 + 다이얼)가 히어로 화면 안, HUD 밖 — `evalHero()` → ok, bad 0, scrRight true
- [x] 극단 상태에서도 화면 숫자가 말이 된다 — 멈춤은 "정지", q 0.0, ∞ 표시 없음

## 남은 문제 (다음 라운드 후보)

1. 효율이 양정비가 작은 극단에서 96%까지 나온다(모델에 누수·공기 손실 없음). 문서에는 적었지만 화면에는 표시하지 않는다.
2. 모바일 히어로에서 앞쪽 콘솔 다이얼 LED가 보케·블룸으로 흰 원 두 개가 된다.
3. 1440×900에서 47 fps — 60 fps를 원하면 GTAO를 반해상도로 돌려야 한다.
