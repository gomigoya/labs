# 개선 계획: 아이스크림 가상실험실 조사 → Lumebench

조사일 2026-10-21. 대상: i-scream.co.kr 「AR·가상실험실」(로그인 후 열람).
근거 구분: **[관찰]** 직접 열어 본 것 / **[추정]** 관찰에서 읽은 것 / **[미확인]** 확인 못 한 것.

## 1. 조사 요약

- 84개 자료, 초3~6 교과서 연계. 학년 필터가 3~6학년뿐이다 [관찰]. 중학교 자료는 목록에서 못 봤다 [관찰].
- 실험 본체는 Unity 2021.3 WebGL, 1024×768 고정 캔버스, 2023-03 제작. Flash가 아니다 [관찰, 2개 실험].
- 교사가 화면에 띄우는 통합뷰어(색연필·판서·화면 가리기·타이머·점수판) 안에서 돈다 [관찰].
- 촛불 끄기: 도구 끌어놓기 → 정해진 연출 → **결론 자막** → 다시 불 붙이기 [관찰, 가위 1회].
  학생이 예측·기록하지 않고 결과 글을 읽는다.
- 지시약 실험은 준비물·안전 장비 슬라이드 뒤 "지시약을 고르세요"까지만 봤다 [관찰]. 이후는 [미확인].
- 조회수: 실험형 평균 약 213, AR형 약 398 (ID 기준 분류는 추정). 실험형 상위는 촛불 끄기 773, 태양광 바람개비 692, 태양계 행성 크기 563, 육지와 바다 넓이 556.
  인기와 학습 효과는 별개라서 수요 신호로만 본다.
- 일반 연구: 시뮬레이션 효과는 수업 설계·교사 진행·실물 실험 병행에 좌우된다. 초등 연구는 적다 (PhET 체계적 리뷰).

## 2. 이미 앞서 있는 것 (유지)

| 항목 | 아이스크림 | 우리 |

| 결과 전달 | 결론 자막을 읽힘 | 예상 후보 → 조작 → 실제와 겹침 (master 5장, forces 쉬운 모드 구현) |
| 조작 | 정해진 도구를 끌어놓기 | 변수를 연속으로 바꾸는 손잡이, 모델은 방정식 하나 |
| 기록·탐구 | 없음 [추정] | 실험 노트, 그래프, 설계 퀘스트(보스) |

## 3. 개선 항목

우선순위: P0 = 기준 불일치 해소, P1 = 작고 효과 큰 것, P2 = 결정·근거가 더 필요한 것.

### P0-1. forces 쉬운 모드를 새 기준으로 맞춘다
- 현재: `docs/quest-map.md`의 쉬운 모드는 퀘스트 이름에 이모지, 소리 읽어 주기(🔊), 설명 문장이 있다.
  `prompts/master-lab-prompt.md`는 이모지·말소리 해설·화면 글자를 금지한다. 같은 프로젝트 안에서 기준이 둘이다.
- 결정 필요(사용자): 기존 forces는 (a) 새 기준으로 이전, (b) "초등 음성 안내판"으로 남기고 새 랩부터 적용 중 택일.
- (a) 선택 시 할 일: 이모지 → 코드 도해 아이콘, 퀘스트 이름 글자 제거, 소리는 효과음·소리화만.
- 완료 기준: 기본 화면 단어 0개(textAudit), 두 모드·모든 퀘스트 단계. `__lab.textAudit()`가 forces에 있는지는 [미확인].

### P1-1. 교과 성취기준으로 탐색하게 한다
- 근거: 아이스크림은 학년·학기·키워드 태그로 찾는다 [관찰].
- 자산: `docs/curriculum/science-2022.csv`(474행, 성취기준 코드).
- 할 일: `meta.json`에 성취기준 코드 배열 추가 → `tools/build.mjs`가 갤러리 필터(학교급·단원)와 sitemap에 반영.
- 완료 기준: 갤러리에서 코드나 단원으로 거른 결과가 `meta.json`과 일치. 현재 갤러리에 필터가 있는지는 [미확인].

### P1-2. 교사 시연에 "화면 가리기"와 타이머를 넣는다
- 근거: 뷰어의 화면 가리기·타이머·점수판이 수업 현장 도구다 [관찰].
- 할 일: 수업 모드(T키 / 시연 모드)에 ① 결과 가리기 = 예상 투표용, ② 타이머를 아이콘으로 추가. 점수판은 만들지 않는다(예상 투표로 대체).
- 완료 기준: 가린 상태에서 조작은 되지만 결과 표시가 숨고, 해제하면 예상 후보와 겹쳐 보인다.

### P1-3. 교사 안내서에 "실물 실험 연결" 칸을 넣는다
- 근거: 시뮬레이션은 실물 실험과 병행할 때 효과가 컸다 (연구 리뷰). 아이스크림에서는 연결 장치를 못 봤다 [추정].
- 할 일: `guide.html`·`master-lab-prompt.md` 산출물에 퀘스트마다 "교실에서 이어 할 실물 활동 1개 + 가상으로만 안전한 이유(해당 시)" 추가. 문서 변경만.
- 완료 기준: forces·hydraulic-ram `guide`의 모든 퀘스트에 칸이 있다.

### P1-4. 다음 랩 후보를 정한다 (수요 신호 + 우리 시각 문법)
- 아이스크림 상위 실험형 주제를 우리 시각 문법에 대 보면:
  - 연소(촛불 끄기): 탈 물질·산소·온도 3조건 → **상쇄·문턱** 문법, 위험 실험이라 가상 가치가 큼.
  - 태양계 크기·거리: **마디·비례 계단**으로 규모를 세게 함.
  - 에너지 전환(태양광 바람개비): **합·보존** 쌓아 채우기.
- 위 세 주제는 아이스크림이 이미 초등용으로 다룬다. 중등용은 목록에서 못 봤다 [관찰]. 그래서 중등 수준(보존·농도·반응 조건)으로 깊이를 올리는 쪽이 겹침이 적다. 주제 선택은 사용자 결정.

### P2-1. 학생 결과를 교사에게 모으는 방법
- 근거: 아이스크림도 학생별 결과 수집이 없어 보인다 [추정]. 교사 모니터링은 기회다.
- 제약: 정적 사이트라 서버가 없다. 최소안은 학생 화면의 진행 결과를 짧은 코드나 링크로 만들어 교사가 모아 보는 방식. 개인정보 이슈 때문에 이름 없이 코드만.
- 결정 필요: 서버 도입 여부(비용·개인정보). 도입 전에 교사 3명 인터뷰로 필요성 확인.

### P2-2. 효과 근거를 직접 만든다
- 연구 리뷰는 설계·교사 역량 의존성을 말한다. 우리 주장("글 없이 이해")은 아직 근거가 내부 5초 테스트뿐이다.
- 할 일: 5초 테스트를 실제 학생 5~10명에게 퀘스트 전·후 캡처로 진행하고 결과를 `review-log.md`에 남긴다.

### P2-3. 화학 랩의 준비·안전 단계
- 근거: 지시약 실험은 시작 전에 실험복·장갑·보안경을 준비물로 보여 준다 [관찰].
- 화학 랩을 만들 때만: 글 없는 아이콘 준비 단계(보안경 → 장갑 → 시작). 지금은 물리 랩만 있어서 보류.

## 4. 하지 않을 것

- 84개처럼 폭을 맞추지 않는다.
- 결론을 자막으로 알려 주지 않는다. 결과는 학생의 예상과 겹쳐 보여 준다.
- 점수판·판서를 새로 만들지 않는다. 투사 화면에 이미 쓰는 일반 도구와 겹친다.
- Unity로 옮기지 않는다. 단일 HTML과 반응형이 우리 강점이다.
- 삽화·이모지·AI 생성 이미지를 쓰지 않는다 (기존 결정).

## 5. 이 조사의 한계

- 열어 본 실험 2개, 끝까지 한 것은 촛불 1개의 가위 한 번뿐이다. 나머지 82개는 제목과 설명만 읽었다.
- 학년별 분포, 실제 사용자 수, 수업 현장 반응은 확인하지 못했다.
- 한국 교사 요구 조사 자료는 찾지 못했다. P2-1은 이 공백 때문에 인터뷰가 먼저다.
