너는 과학 커뮤니케이터, 실시간 3D 아티스트, 테크니컬 아티스트(셰이더), 전시 UI 디자이너, 교육 설계자로 구성된 한 팀이다.
맨 아래 <theory>의 이론 하나를 웹 3D 실험실로 만든다. 글을 전혀 모르는 사람도 손으로 조작하기만 하면 원리를 눈으로 알아채야 한다.
사용자는 둘이다.
- 학생: 직접 조작하고 퀘스트를 진행하며 원리를 발견한다.
- 교사: 같은 실험실을 조작하며 아이들 앞에서 원리를 설명한다.
목표 품질은 "과학관 상설 전시용 인터랙티브 + 고급 제품 렌더" 수준이다. 참고 사이트는 없고, 아래 명세가 기준이다.
나에게 질문하지 말고 끝까지 진행하라. 애매한 결정은 직접 내리고 README의 "결정 기록"에 남겨라.
품질은 비싼 에셋이 아니라 조명·재질·구도·셰이더·시각 문법의 공정에서 나온다. 외부 모델·이미지 없이 전부 코드로 만든다.

0. 핵심 철학
══════════════════════════════════════
1. 글 없이 읽힌다: 화면에 단어가 없다. 원리는 모양의 비교(길다/짧다, 같다/다르다, 넓다/좁다, 넘친다/모자란다)로 전달한다.
   언어 중립이므로 어느 나라 전시관에서도 그대로 쓴다.
2. 손이 원인, 장면이 결과: 사용자가 장치를 직접 끌고 돌리고 넣는다. 결과는 손을 움직이는 그 순간 함께 변한다.
   원인과 결과가 같은 순간, 같은 자리에 보여야 인과가 읽힌다.
3. 보이지 않는 것을 보이게: 이론의 숨은 양(힘, 장, 압력, 위상, 확률, 흐름, 에너지…)을 화면의 주인공으로 꺼낸다.
4. 비교로 이해한다: 하나의 값은 의미가 없다. 바꾸기 전과 후, 예상과 실제, 한계와 지금을 같은 자리에 겹쳐 보여 준다.
5. 방정식이 유일한 진실의 원천: 모든 크기·색·위치·판정은 하나의 물리 모듈(순수 함수)에서 계산한다. 손으로 맞춘 값은 금지한다.
6. 진짜 기계처럼: 사용자는 실험실 방 안의 계측 콘솔 위에 놓인 장치를 만진다. 그래프는 콘솔 화면 안에 있다.
7. 정직한 과장: 과장한 스케일은 장면 안에 기호(⤢ 확대 표식)로 표시하고, 교사 안내서에 밝힌다.

1. '글자 0' 규칙 (최우선 · 자동 검사)
══════════════════════════════════════
* 학생 모드와 교사 모드의 기본 화면에서 보이는 단어는 0개다. 아래가 모두 해당한다.
  - 제목, 헤드라인, 리드, 캡션, 라벨, 버튼 글자, 툴팁, 단축키 표시, 단위 문자(N, cm, s…), 장면 속 명판·화면의 글자.
* 허용하는 것: 아이콘, 색, 모양, 개수, 진행 점, 그리고 실제 계측기처럼 기구에 새겨진 눈금 숫자.
  - 교사 모드의 '수치 층'(기본 꺼짐)을 켰을 때만 숫자와 단위 기호가 뜬다.
* 이해가 숫자를 읽는 데 기대면 안 된다. 모든 크기는 셀 수 있는 마디·길이·개수로도 읽혀야 한다.
* 버튼마다 aria-label(ko/en)을 단다. 화면에는 보이지 않는다.
* 말소리 해설은 넣지 않는다. 소리는 효과음과 소리화(음높이 = 크기, 마디마다 틱)만 쓰고, 소리를 꺼도 완전히 이해되게 한다.
* 글이 필요한 내용(성취기준, 발문, 오개념, 시연 순서, 과장·근사)은 모두 화면 밖 문서로 옮긴다: guide.html(교사 안내서), README, docs.
* 금지: 삽화, 캐릭터, 마스코트, AI 생성 이미지, 클립아트, 사진, 이모지(OS마다 모양이 다르고 유치하다).
  모든 그림은 코드로 그린 계측·도해 양식(선화 + 평면 채색 + 모눈)만 쓴다.
* 자동 검사 `__lab.textAudit()`:
  - 보이는 텍스트 노드를 TreeWalker로 모아 단어(문자 2자 이상)가 있으면 그 위치를 반환한다.
  - 모든 퀘스트 단계와 두 모드에서 0이어야 완료다.

2. 이론 해부 (docs/theory-card.md — 코드 전에, 기다리지 말고 진행. 문서라서 글로 쓴다)
══════════════════════════════════════
 a. 한 줄 통찰
 b. 3단계 학습 경로: 알아챌 현상 → 조작하며 발견할 규칙 → 비교로 확인할 법칙
 c. 보이지 않는 주인공과 그 시각 형태

 e. 지배 방정식 2~5개(단위·범위·근사)

 g. 원리 → 시각 문법 대응표: 각 원리를 3장의 사전에서 어떤 표현으로 보여 줄지
 h. 퀘스트 목록(5장): 학습 질문, 조작, 관찰 증거, 완료 조건
 i. 예상 그림 후보: 퀘스트마다 2~3개. 흔한 오해 하나를 반드시 후보에 넣는다
 j. 원리 카드: 퀘스트마다 그림 등식 1장(예: 마디 2개 → + 마디 1개 ← = 마디 1개 →)
 k. 콘솔 그래프 2개: x/y가 무엇이고 축 끝에 어떤 아이콘을 둘지
 l. 현상 셰이더 설계: 매질(반투명/발광), 흐름 입자, 물리량→색 매핑
 m. 교사 시연 순서(guide.html용): 퀘스트별 발문 1개, 켤 표현 층 순서, A/B 비교 장면
 n. 흔한 오해 2개와 그 오해를 깨는 장면
 o. 과장 스케일 목록 p. 카메라 샷 6개 + 세로 3개 q. 방 소품 6~10개(주제와 연결된 것 포함)

3. 시각 문법 (범용 사전 — 글이 하던 일을 이 표현들이 한다)
══════════════════════════════════════
일관성 규칙
* 같은 뜻은 어디서나 같은 모양이다.
  - 실선·발광은 지금 작용하는 양이다.
  - 점선 윤곽은 기준이다: 바꾸기 전 값, 최대 한계, 예상.
  - 회색 잔상은 지나간 시간이다.
* 색은 양의 정체성이다. 한 양은 화살표·막대·그래프 선·손잡이·도구대 아이콘에서 모두 같은 색이다.
  - 색각 이상을 위해 명도 차와 모양(굵기·무늬·끝 모양)으로도 구분한다.
* 화면에 동시에 켜진 표현은 원리 하나에 필요한 것만 둔다. 결정적 순간에는 하나만 남긴다.

표현 사전. 이론에 맞는 것만 고른다. 없는 원리를 억지로 만들지 않는다.
| 원리 유형 | 표현 | 예시 분야 |
|---|---|---|
| 크기 | 마디: 양을 길이로 그리고 같은 단위마다 눈금 → 마디 수를 센다 | 힘, 전류, 에너지, 농도 |
| 비교 | 겹치기: 바꾸기 전 값이 점선 윤곽으로 남고 지금 값이 그 안팎으로 변한다. 교사는 A/B를 고정해 겹친다 | 모든 분야 |
| 합·보존 | 쌓아 채우기: 부분들을 이어 붙여 전체(점선)를 정확히 채운다 | 힘의 평형, 에너지 보존, 질량 보존, 회로 전압 |
| 상쇄 | 마주 보는 두 양의 겹친 부분이 사라지고 남는 만큼만 결과가 된다. 정확히 상쇄되면 →← 기호 | 평형, 간섭, 중화 |
| 비례 | 계단: 원인을 한 단위씩 늘릴 때마다 결과 위치에 눈금을 남긴다 → 간격이 같으면 비례 | 훅 법칙, 옴 법칙, 반응 속도 |
| 문턱 | 한계 윤곽: 넘을 수 없는 최대치를 점선으로. 실선이 차오르다 넘치는 순간 사건(슬로·번쩍·소리)이 일어난다 | 정지 마찰, 임계각, 활성화 에너지, 탈출 속도 |
| 시간·운동 | 같은 시간 간격 흔적: 점·잔상·궤적 → 간격이 넓어지면 빨라짐. 방향이 다르면 줄을 나눈다 | 운동, 진동, 확산 |
| 확률·분포 | 반복 시행: 결과 하나하나가 낙하해 쌓이며 분포가 자란다 | 유전, 붕괴, 기체 분자, 측정 오차 |
| 숨은 구조 | 돋보기 렌즈: 원이 열리며 단면 도해(모눈 + 선화 + 평면색, 코드로 그림)가 실제 수치와 함께 움직인다 | 마찰면, 분자, 세포, 결정, 회로 내부 |
| 장·흐름 | 방향 입자 흐름. 세기는 밀도·밝기, 등위면은 얇은 선 | 전기장, 유체, 열, 빛 |
| 상태 변화 | 같은 물체의 전·후를 나란히 고정(박제)해 둔다 | 상변화, 화학 반응, 굴절 |
| 기록 | 실험 노트: 시행마다 한 줄(조건 아이콘 + 결과 막대) 자동 기록, 바꾼 조건만 테두리 강조, 두 개 이상 바꾸면 ⚠ 아이콘 | 모든 탐구 |
| 그래프 | 축 끝에 양의 아이콘, 선은 양의 색, 현재값 커서, 숫자 없는 격자(수치 층에서만 숫자) | 모든 분야 |

4. 두 모드 (같은 장면·같은 물리, 도구만 다르다)
══════════════════════════════════════
학생 '탐험' 모드 (기본)
* 퀘스트를 진행하는 길(5장)과 자유 실험을 상단의 두 아이콘으로 오간다.
* 자유 실험에서는 그 장치의 모든 조작이 열린다. 퀘스트 중에도 다른 조작은 은은하게 남아 더 해 볼 수 있다.
* 퀘스트를 마치면 원리 카드를 모은다. 카드 슬롯이 하단 오른쪽에 아이콘 줄로 보인다.

교사 '시연' 모드 (전자칠판·프로젝터 1920×1080, 5~8 m 거리에서 읽히게)
* 손잡이·아이콘·선 굵기를 1.4배로 키우고 대비를 높인다.
* 시연 도구: 화면 오른쪽 세로 도구 띠에 아이콘만 둔다.
  - ⏸ 정지 / ◁▷ 한 프레임 / 슬로 0.25×
  - 표현 층 켜고 끄기: 힘 마디, 한계, 잔상, 렌즈, 노트를 하나씩 쌓아 가며 설명한다
  - A/B 고정: 지금 상태를 점선으로 박제하고 조건 하나를 바꿔 겹친다
  - 스포트라이트: 가리킨 곳만 밝히고 나머지를 어둡게 한다
  - 레이저 포인터 / 수치 층 / 퀘스트 바로가기(퀘스트 아이콘 격자) / 처음 상태로
* 학급 예상: 예상 그림 후보를 화면 가득 크게 띄워 학생들이 손을 들게 한다.
  교사가 고르면 실행하고, 결과를 후보와 겹쳐 보여 준다.
* 교사용 글은 guide.html에만 둔다. 교사의 개인 화면에서 여는 문서이고 투사 화면에는 띄우지 않는다.
  - 성취기준, 퀘스트별 발문, 오개념, 시연 순서, 과장·근사, 평가 아이디어를 담는다.

5. 글 없는 퀘스트 (docs/quest-map.md를 코드 전에 확정)
══════════════════════════════════════
<theory>를 먼저 분석하고 그 이론에 맞는 직접 조작 퀘스트를 설계하라. 이전 실험실의 장치·주기·흐름을 다른 이론에 그대로 옮기지 마라.
연결표: 학습 질문 → 조작 가능한 원인 → 장면 속 조작 대상과 행동 → 지배 방정식 또는 모델 → 시각 문법 표현 → 관찰 증거 → 완료 조건.
한 단계에는 의미 있는 행동 하나만 둔다. 단계 수는 학습에 필요한 만큼만 정한다(보통 6~10개). 마지막 퀘스트는 조건을 골라 목표를 이루는 설계 과제로 한다.

퀘스트 한 개의 흐름 (글 없이)
 ① 장면 제시: 카메라가 넓게 보여 준 뒤 장치로 밀고 들어간다. 이번에 만질 부품만 빛나고 나머지는 차분해진다.
    상단 띠에는 퀘스트 아이콘(장치 픽토그램)과 진행 점만 보인다.
 ② 예상: 결과 후보 그림 2~3개가 뜬다.
    - 같은 시뮬레이션을 작은 화면에서 각 조건으로 미리 돌린 짧은 루프다. 그림 파일을 쓰지 않는다.
    - 하나를 고르기 전에는 장치가 잠기고, 만지면 후보 카드가 살짝 흔들린다.
 ③ 조작: 유령 손이 끄는 방향을 한 번 시범으로 보인다. 목표가 있으면 목표 윤곽(점선)이나 깃발 눈금을 레일에 둔다.
    7초 동안 손을 대지 않으면 시범을 한 번 더 보인다.
 ④ 관찰: 과학적 사건(문턱 넘음, 평형 도달, 상태 변화)이 일어나는 순간에 연출이 붙는다(7장).
    - 슬로 모션, 해설 기호 하나, 필요하면 돋보기 렌즈.
 ⑤ 확인: 고른 예상 그림이 실제 장면 옆으로 날아와 겹친다.
    - 맞으면 ✓ 도장과 밝은 화음이 나온다.
    - 다르면 두 그림을 나란히 남기고 ↺ 다시 보기 버튼을 둔다. 감점하지 않는다. 결과를 보고 생각을 고치는 것이 과학이다.
 ⑥ 원리 카드: 이번 원리를 그림 등식 한 장으로 받는다. 같은 시각 문법으로 그리고 글자는 넣지 않는다.
* 완료 조건은 물리 모듈의 결과로 판정한다(예: 두 양의 차 ≤ 허용오차, 상태 지속 시간). 화면 연출로 판정하지 않는다.
* 퀘스트를 마쳐도 사용자가 만든 조건은 유지한다. 다음 퀘스트로 넘어갈 때만 그 퀘스트의 시작 상태를 세운다.
* 시간 변화가 핵심이면 재생한다. 정적 관계가 핵심이면 비교·계단을 쓴다. 확률이 핵심이면 반복 시행과 분포를 쓴다.
* 진행 지도: 상단 띠의 퀘스트 아이콘 줄(완료 = 채움, 지금 = 빛남). 점수가 있다면 별 개수로만 보인다.

══════════════════════════════════════
6. 아트 디렉션 (고정 — 수치를 지켜라)
══════════════════════════════════════
구도
* 첫 화면에서 영웅 장치가 화면 면적의 60~75%를 차지한다. 3/4 시점, 수평에서 10~25° 위, FOV 30~38°.
* 프레임 가장자리에서 잘리는 물체가 2개 이상이다(콘솔 앞부분, 앞쪽 소품) → 세계가 화면 밖으로 이어진다.
* 장치 뒤 배경은 피사계 심도로 부드럽게 흐린다(깊이 기반 보케, 장치는 선명).
* 장치는 상단 퀘스트 띠와 하단 도구대 사이의 빈 띠 중앙에 둔다. 띠 높이에 맞춰 카메라 오프셋(view offset)으로 맞춘다.
* 실험 중에는 지금 쓰는 장치만 밝고 선명하다. 나머지 방은 깊이에 따라 어둡고 채도가 낮다.

무대: 실험실 방 (빈 허공 금지)
* 벽 2면 + 바닥이 보이는 방. 창문 1개(바깥 낮빛 그라데이션, 창틀), 선반 1~2개, 화분, 유리병·기하 오브젝트,
  벽에 걸린 도식 패널(이론 다이어그램이 은은히 빛나는 화면, 글자 없이 기호와 선) 2~3개, 스탠드 램프 또는 펜던트 1개.
* 소품은 로우폴리에 둥근 모서리로 만들고, 주제와 연결된 것을 1~2개 넣는다. 배경 밝기는 중간이다(검정이 아닌 따뜻한 갈색·회색).

계측 콘솔 (조작계가 세계 안에 있다)
* 장치는 콘솔 위나 안에 놓인다. 콘솔 앞면 구성:
  - 큰 다이얼 1~2개: 둥근 노브 + 값만큼 채워지는 발광 원호
  - 가로형 실시간 그래프 화면 1~2개: 어두운 화면 + 격자 + 축 끝 아이콘 + 발광 곡선 + 현재값 커서
  - LED 트랙 물리 슬라이더: 크롬 손잡이 + 아래 삼각 마커
  - 황동 테두리 큰 버튼: 재생/일시정지
  - 금속 명판 띠: 글자 대신 이론을 상징하는 기호·도식을 각인한다
* 장면 속 손잡이, 콘솔의 다이얼·슬라이더, 그래프는 항상 같은 상태를 보여 준다(같은 물리 모듈에서 계산).
* 콘솔 부품도 마우스·터치로 직접 돌리고 끌 수 있다.

조명 레시피
* 따뜻한 키(호박·주황 #ffb36b 계열) vs 차가운 현상광(하늘·청 #7dd3fc 계열)의 보색 대비로 화면 전체를 짠다.
* 화면에 보이는 실용 광원이 4개 이상이다(전구, 램프, LED 띠, 발광 화면, 다이얼 원호, 장치 내부광). 각각 실제 PointLight나 RectAreaLight를 동반한다.
* 앰비언트 오클루전(GTAOPass 또는 SSAO)으로 접촉 그림자를 만든다. 그림자 맵은 1~2개(PCF soft).
* 블룸은 발광 부품과 현상에만 쓴다(threshold ≈ 0.85~0.9, 발광색 ×2~4). 나머지 표면은 무광. ACES 톤매핑, RoomEnvironment 환경맵.
* 가장자리 비네트, 아주 약한 필름 그레인(선택).

재질
* 기계 부품 모서리는 전부 둥글게 만든다(RoundedBoxGeometry, 베벨 Extrude, Lathe). 날카로운 CG 박스는 금지한다.
* 팔레트: 짙은 흑연 금속(무광, roughness 0.5~0.7) + 황동·금 포인트(metalness 1, roughness 0.3) + 크롬 + 유리(transmission). 자연물은 플랫 셰이딩 로우폴리.
* 큰 면을 단색으로 비우지 않는다: 패널 이음선, 나사 머리, 통풍 슬릿, 눈금, 기호 각인, 고무 패드 같은 미세 디테일을 넣는다.

현상 셰이더 (주인공)
* 주인공 현상은 반드시 전용 ShaderMaterial로 그린다.
  ① 반투명·발광 매질
  ② 흐름을 보여 주는 입자(InstancedMesh 또는 Points, 방향 스트릭)
  ③ 물리량→색 매핑(파장→스펙트럼, 온도→흑체색, 세기→밝기, 위상→색상환 등)
* 가산 혼합 + 블룸으로 빛나되, 코어는 선명하게 유지해 형태가 뭉개지지 않게 한다.
* 양을 나타내는 화살표·막대 셰이더는 마디 눈금(uUnit)과 점선 윤곽 스타일(uStyle)을 지원한다(3장).

전시 UI 디자인 시스템 (글자 대신)
* 화면에 고정된 UI는 세 곳뿐이다. 나머지 조작은 장면 속 손잡이로 한다.
  - 상단 중앙 퀘스트 띠: 모드 아이콘 2개 + 퀘스트 아이콘 줄 + 진행 점
  - 하단 중앙 도구대: 고르기·개수 조절
  - 교사 모드의 오른쪽 도구 띠
* 장면 속 손잡이: 끄는 것(힘, 높이, 각도, 양)은 장치 옆에 붙은 레일 + 둥근 손잡이로 만든다.
  - 레일에는 눈금 숫자만 둔다.
  - 손잡이는 3D 물체를 정확히 맞히지 않아도 잡힌다(넉넉한 히트 영역).
* 도구대: 고르기는 재질·대상 견본(코드로 그린 작은 단면이나 색 견본), 개수는 − / + 와 개수만큼의 점.
  - 누르는 동안 버튼 위치가 변하지 않는다.
  - 조건을 바꿔도 다른 조건은 초기화하지 않는다.
* 아이콘: 한 벌로 코드에 둔다(24px 격자 SVG path, stroke 2, round cap). 의미가 한눈에 보이는 계측·동작 기호만 쓴다.
* 표면: 흰 카드 또는 반투명 유리(blur 14px), 둥근 14~18px, 그림자 하나. 강조색은 하나만, 양의 색과 겹치지 않게.
* 터치 타깃은 56px 이상(교사 모드 72px)이다. 호버에 의존하는 기능은 없다. 키보드 없이 끝까지 할 수 있어야 한다(단축키는 보조이고 화면에 표시하지 않는다).
* 숫자 눈금 폰트는 DM Mono(tabular-nums) 하나만 쓴다. 단어용 폰트는 필요 없다.
* 모바일(≤980px): 도구대는 두 줄로 접고, 세로 화면은 세로 전용 히어로 샷을 쓴다.

전시 운영 (키오스크)
* 대기 화면(attract): 90초 동안 조작이 없으면 시네마틱 루프로 넘어간다.
  - 장치가 스스로 움직이며 핵심 현상을 시연한다.
  - 화면을 만지면 손 모양 맥동 하나로 시작을 알린다.
* 대기에서 돌아오면 처음 상태로 초기화한다. 진행 저장은 같은 세션 안에서만 한다.
* 성능 저하나 오류 때도 글 대신 아이콘 상태(↺)를 보여 준다.

══════════════════════════════════════
7. 연출 (과학적 사건에만)
══════════════════════════════════════
* 연출은 "언제 무엇을 볼지"를 알려 주는 도구다. 장식용 연출은 넣지 않는다.
* 사건은 물리 모듈의 상태 전이에서 나온다. 예: 정지→움직임, 문턱 넘음, 평형 도달, 잠김·뜸, 반응 시작.
* 기법
  - 슬로 모션: 물리만 느리게, 카메라·화면은 실제 시간
  - 짧은 카메라 밀기·따라가기
  - 해설 기호: 점 → 선 → 기호 상자 하나, 실제 값만큼의 마디
  - 입자(먼지, 물보라, 충격 링), 사건음
* 결정적 순간에는 해설을 하나만 남긴다. 다른 이름표·도구대는 흐리게 하고 해설은 모든 UI 위에 둔다.
* 퀘스트 시작: 레터박스 + 퀘스트 아이콘 와이프(글자 없음) → 넓은 화면 0.9초 → 장치로 밀고 들어가기 1.8초.
* 실시간 텔레메트리: 지금 퀘스트의 핵심 양 1~2개를 하단 미니 그래프(색 선, 축 아이콘)로 보여 주고, 사건 순간에 표식을 찍는다.

══════════════════════════════════════
8. 엔진 (고정)
══════════════════════════════════════
* 단일 index.html + guide.html(교사 안내서). Three.js 최신 안정판(r17x 이상)을 importmap(cdn.jsdelivr.net)으로 쓰고, 빌드 도구는 쓰지 않는다.
  - addons: OrbitControls, RoomEnvironment, EffectComposer, RenderPass, GTAOPass(또는 SAOPass), BokehPass 또는 자체 DoF,
    UnrealBloomPass, OutputPass, RoundedBoxGeometry, RectAreaLightUniformsLib, LineSegments2 계열.
* 외부 모델·이미지는 0개다. 화면·눈금·각인·창밖 하늘은 캔버스 텍스처로 만든다. 시드 고정 난수(mulberry32)를 쓰고 Math.random은 금지한다.
* 규모: 3,000~5,000줄을 허용한다. 짧게 줄이느라 디테일을 빼지 마라.
* 스크립트 섹션 순서:
  1 PHYSICS → 2 SCENE/RENDERER → 3 KIT → 4 ROOM → 5 CONSOLE → 6 HERO APPARATUS → 7 PHENOMENON SHADERS
  → 8 OVERLAYS(시각 문법) → 9 LIGHTS → 10 PIPELINE → 11 CAMERA/SHOTS → 12 INTERACTION(손잡이·도구대)
  → 13 QUESTS(학생) → 14 PRESENTER(교사) → 15 DIRECTOR(연출) → 16 HUD(아이콘 UI) → 17 LOOP.
* KIT에 먼저 만들 부품 함수(재사용):
  - 장면 부품: roundedPanel, bevelFrame, screw, ventSlits, engravedSymbol, knobWithArc, ledSlider, graphScreen(drawFn),
    bigButton, brassTrim, lampWithBulb, ledStrip, glassJar, plant, shelf, windowWithSky, wallDiagramPanel, rubberFoot
  - 시각 문법: quantityArrow(마디·점선), ghostOutline, limitOutline, stepMarks, timeDots, lensSection(svg)
  - UI: icon(name)
  장면은 이 부품의 조립으로만 만든다.
* state: 변수마다 현재/목표값 쌍을 두고 매 프레임 지수 감쇠한다. 시간 현상은 t의 순수 함수 + 일시정지·속도(0.25×~2×)로 만든다.
* 렌더 레이어: 방 / 콘솔·장치 / 투명 / 설명 오버레이. 설명 오버레이는 DoF 등 화면 효과 다음에 깊이 테스트하며 합성한다.
* 장치 단면: 앞/뒤 반쪽으로 나눠 만든다. '분해' 시 앞쪽이 빠지며 투명해지고 내부 부품이 축 방향으로 벌어진다.
* 소리(기본 꺼짐, 아이콘으로 켬): WebAudio로 손잡이 틱(마디마다), 끄는 동안 크기에 따라 올라가는 톤, 사건음, 성공 화음.
* 성능: 픽셀 비율 상한 1.6. 2초 평균 프레임이 32ms를 넘으면 AO 끄기 → 픽셀 비율 1 → 보케 끄기 순으로 자동 하향한다.
* 디버그·검증 훅(필수): 렌더 루프를 frame()(requestAnimationFrame 담당)과 update(dt)(한 프레임 계산 + 렌더)로 분리한다.
  window.__lab = {
    state, set(name, v), preset(i), view(mode), flyTo(shot), SHOTS, SHOTS_VERTICAL,
    mode(m),              // 'explore' | 'present'
    quest: { go(i), i, passed, pick(k) },   // 퀘스트 이동, 예상 고르기
    layer(name, on),      // 시각 문법 층 켜고 끄기
    textAudit(),          // 보이는 단어 목록 (0이어야 함)
    step(n, dt),          // rAF 없이 n프레임 진행
    shot(i),              // 카메라를 샷 i로 즉시 이동
    capture(name)         // 캔버스 크기가 0이거나 창 크기와 다르면 먼저 리사이즈 → update 1회
                          // → canvas.toDataURL을 POST /__save/<name>.jpg 로 보내 shots/에 저장
  }.
  검증 스크립트 한 번은 짧게 돌린다. step은 120프레임 이하씩 나눠 호출하고, 카메라 후보 탐색은 렌더링 없이 투영만 계산한다.
  (이유: 브라우저 창이 가려지면 rAF와 CSS 애니메이션이 멈추고 스크린샷이 예전 프레임으로 남아 검증이 거짓말을 한다.)

구현 함정 (실전에서 실제로 터진 것들)
* 물리로 위치가 정해지는 물체를 '분해 보기' 위치 복원 목록에 넣지 마라. 연출 오프셋은 별도 부모 그룹에 건다.
* 히어로 시점에서 현상 앞에 오는 불투명 부품은 현상보다 낮고 좁게 만든다. 카메라는 현상면을 15~30° 위에서 내려다본다.
* 가산 발광 + 블룸은 쉽게 하얗게 포화된다. 상태별로 발광 총량을 정규화하고, 가까이·위에서 찍은 캡처로 확인한다.
  장치 옆 포인트 라이트와 뒤쪽 림 스폿은 약하게 둔다. 강하면 광택면에 하얀 띠가 생긴다.
* 방 소품은 히어로 카메라가 실제로 보는 벽 띠에 둔다(3D 좌표를 화면에 투영해 확인).
* 안개 시작 거리는 카메라~뒷벽 거리보다 멀게 잡는다. 노출 0.8~0.9, 블룸 threshold 0.9 이상에서 시작한다.
* 시뮬레이션에서 "측정"하는 값은 경계 조건을 처리한다.
  ① 반복 실행은 실행 번호로 구분한다.
  ② 특이점(공명, 임계)은 값 대신 사건으로 바꾼다.
  ③ 데이터가 없으면 빈 상태로 둔다.
* 순간 사건(미끄러짐 시작 등)은 연출 쿨다운보다 먼저 기록한다. 안 그러면 노트에서 빠진다.
* 손잡이 하나만 잡을 수 있는 마우스로 '양쪽을 맞추는' 퀘스트는 손을 뗀 뒤 잠시(1~1.5초) 결과를 보류하는 고정 핀이 필요하다.
* 새 해설·렌즈가 열리면 이전 것을 즉시 닫는다. 참조를 잃은 요소가 화면에 남는다.
* 설명 그림을 그림 파일로 넣고 싶어지면 코드로 그린 도해로 대신하라. 생성 삽화는 실험실의 격을 떨어뜨린다.
* 세로(모바일) 화면은 상단 띠와 하단 도구대 사이 빈 띠가 좁다. 세로 전용 히어로 샷과 두 줄 도구대를 처음부터 설계한다.
* 히어로 구도는 렌더링 없이 투영 계산으로 고른다.
  - 카메라 후보 수백 개 중에서 장치 끝점과 비교 대상이 상단 띠·하단 도구대 밖에 들어오는 후보 가운데 가장 크게 잡히는 것을 쓴다.

9. 제작 순서 (단계마다 캡처를 찍어 직접 보고 넘어간다)
══════════════════════════════════════
 1 블록아웃: 회색 박스로 방·콘솔·장치를 배치하고 히어로 카메라 구도를 확정한다(장치 60~75%, 가장자리 잘림 확인).
 2 조명: 키/보조/실용 광원/AO/블룸. 회색 재질 상태에서도 보색 대비와 깊이가 보여야 다음으로 넘어간다.
 3 재질·디테일: KIT 부품으로 교체하고 둥근 모서리, 미세 디테일, 황동 포인트를 넣는다.
 4 현상 셰이더: 주인공 현상, 흐름 입자, 물리량→색 매핑.
 5 장면 속 손잡이와 도구대: 모든 조작 변수를 직접 조작으로 연결한다(이 단계까지 글자 0).
 6 시각 문법 층: 3장의 표현을 이론에 맞게 구현하고 층마다 켜고 끈다.
 7 퀘스트: 예상 후보 루프, 유령 손, 목표 윤곽, 확인 겹침, 원리 카드, 진행 지도.
 8 연출: 사건 감지, 슬로 모션, 해설 기호, 렌즈, 텔레메트리.
 9 교사 시연 모드와 guide.html.
10 다듬기: 대기 화면, 모바일, 성능, 소리, 등장 애니메이션.

10. 비평 루프 (최소 3라운드, 모든 항목 8점 이상까지)
══════════════════════════════════════
* 로컬 서버를 직접 만든다: 정적 파일 제공 + POST /__save/<name> 으로 받은 data URL을 shots/<name>에 저장하는 기능.
* 3D 화면은 __lab.step/shot/capture로 shots/*.jpg를 만들어 파일로 열어 본다. HUD 배치는 브라우저 스크린샷 + getBoundingClientRect로 확인한다.
* 해상도: 1920×1080(교사), 1440×900, 375×812에서 확인한다.
  - 확인할 장면: 히어로 / 퀘스트 전부(시작·예상·조작 중·사건 순간·확인·원리 카드) / 자유 실험 극단값 / 분해 / 교사 도구 각각 / 대기 화면.
  - 콘솔 에러 0, 가로 스크롤 0, textAudit() 0.
* 글 가리고 5초 테스트: 퀘스트마다 소리를 끈 캡처 2장(조작 전·후)만 보고 원리를 한 문장으로 말할 수 있는지 판정한다.
  말할 수 없으면 그 퀘스트의 시각 문법을 고친다. 글을 더하는 것은 해법이 아니다.
* 시각 판정 체크리스트(하나라도 아니면 그 문제부터 고친다):
  □ 기본 화면 단어 0개(두 모드, 모든 퀘스트 단계)  □ 장치가 화면의 60% 이상
  □ 프레임에서 잘리는 물체 2개 이상  □ 보이는 실용 광원 4개 이상  □ 따뜻한/차가운 보색 대비
  □ 배경에 흐린 소품 5개 이상, 검은 허공 없음  □ 단색으로 빈 큰 면 없음
  □ 현상이 전용 셰이더로 빛나고 흐름이 보인다  □ 모든 조작 변수를 장면 속 손잡이나 도구대로 만질 수 있다
  □ 퀘스트마다 예상 후보 → 조작 → 사건 → 확인 겹침 → 원리 카드가 글 없이 이어진다
  □ 크기는 셀 수 있다(마디·개수)  □ 비교 대상이 같은 자리에 겹쳐 보인다
  □ 결정적 순간에 해설이 하나뿐이다  □ 교사 모드가 5 m 거리에서 읽힌다(선·아이콘 굵기)
  □ 색으로만 구분하는 곳이 없다(모양·명도 이중 부호화)  □ 모바일에서 장치 전체와 도구대가 보인다
  □ 삽화·캐릭터·이모지·사진 0개  □ 극단 상태에서도 표현이 말이 된다(화면 밖으로 뻗는 화살표 없음)
* 점수 1~10:
  ①무글자 이해(5초 테스트) ②원리 전달력 ③물리 정확성 ④퀘스트 흐름 ⑤교사 시연성 ⑥구도 ⑦조명
  ⑧재질·디테일 ⑨현상 셰이더 ⑩전시 UI ⑪모션·연출 ⑫모바일·성능
  자랑스러운 작가가 아니라 냉정한 아트 디렉터와, 글을 모르는 일곱 살의 눈으로 매긴다.

* 물리 검증표: 대표 상태 3개의 내부 값을 별도 JS 스니펫 손계산과 비교한다. 어긋나면 물리 모듈을 고친다.
