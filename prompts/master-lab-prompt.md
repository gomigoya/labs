너는 과학 커뮤니케이터, 실시간 3D 아티스트, 테크니컬 아티스트(셰이더), UI 디자이너, 교육 설계자로 구성된 한 팀이다.
맨 아래 <theory>의 이론 하나를, 처음 보는 사람이 직접 손으로 조작하며 원리를 눈으로 보고 이해하는 웹 실험실로 만든다.
목표 품질은 "박물관 전시용 인터랙티브 + 고급 제품 렌더" 수준이다. 참고 사이트는 없고, 아래 명세가 기준이다.
나에게 질문하지 말고 끝까지 진행하라. 애매한 결정은 직접 내리고 README의 "결정 기록"에 남겨라.
품질은 비싼 에셋이 아니라 조명·재질·구도·셰이더·UI의 공정에서 나온다. 외부 모델·이미지 없이 전부 코드로 만든다.

0. 핵심 철학
══════════════════════════════════════

1. 보이지 않는 것을 보이게: 이론의 핵심인 숨은 양(위상, 장, 압력, 확률, 흐름, 시공간…)을 화면의 주인공으로 꺼낸다.
2. 원인 → 메커니즘 → 결과가 한 화면에 동시에.
3. 방정식이 유일한 진실의 원천: 모든 숫자·크기·색·문장은 하나의 물리 모듈(순수 함수)에서 계산. 손으로 맞춘 값 금지.
4. 진짜 기계처럼: 사용자는 실험실 방 안의 계측 콘솔 위에 놓인 장치를 만진다. 그래프는 콘솔 화면 안에.
5. 정직한 과장: 과장한 스케일은 도움말에 밝힌다.

1. 이론 해부 (docs/theory-card.md — 코드 전에, 기다리지 말고 진행)
══════════════════════════════════════
 a. 한 줄 통찰 b. 3단계 학습 경로(알아챌 현상 → 조작하며 발견할 규칙 → 숫자로 확인할 법칙)
 c. 보이지 않는 주인공 + 시각 형태 d. 영웅 장치 1개(단면·분해 가능) + 그것이 놓일 실험실 방의 성격
 e. 지배 방정식 2~5개(단위·범위·근사)
 f. 조작 변수 2~3개: 3D 부품 직접 드래그 / 이야기형 프리셋 3~4개 / 연속 슬라이더 / 단축키
 g. 이야기형 시나리오 프리셋 3~4개: 숫자가 아니라 이름("좁게·이상적·넓게", "보강·상쇄·흐려짐"처럼). 각각 원리 하나를 보여 줌.
 h. 오버레이 토글 2~3개: 숨은 양을 켜고 끄는 층(예: 위상, 세기, 단면).
 i. 수치 칩 3개: 큰 값 + 아래 작은 보조 값 한 줄.
 j. 콘솔 화면 2개에 그릴 실시간 그래프(무엇을 x/y로).
 k. 현상 셰이더 설계: 주인공 현상을 그리는 전용 셰이더 — 매질(반투명/발광), 흐름 입자, 물리량→색 매핑.
 l. 캡션 상태기계(실제 숫자가 들어간 완결 문장) m. 가이드 투어 5~7단계 n. 흔한 오해 2개
 o. 헤드라인: 작은 킥커(이론 이름) + 큰 동사형 훅(무엇이 일어나는지, 한국어 2~8자 또는 2줄 이내)
 p. 과장 스케일 목록 q. 카메라 샷 6개 r. 방 소품 6~10개(주제와 연결된 것 포함)

══════════════════════════════════════
2. 아트 디렉션 (고정 — 수치를 지켜라)
══════════════════════════════════════
구도

* 첫 화면에서 영웅 장치가 화면 면적의 60~75%를 차지한다. 3/4 시점, 수평에서 10~25° 위, FOV 30~38°.
* 프레임 가장자리에서 잘리는 물체 2개 이상(콘솔 앞부분, 앞쪽 소품) → 세계가 화면 밖으로 이어진다.
* 장치 뒤 배경은 피사계 심도로 부드럽게 흐린다(깊이 기반 보케, 장치는 선명).
* 왼쪽 위 텍스트와 오른쪽 위 패널이 겹치지 않는 자리에 장치를 둔다(중앙~약간 아래).

무대: 실험실 방 (빈 허공 금지)

* 벽 2면 + 바닥이 보이는 방. 창문 1개(바깥 낮빛 그라데이션, 창틀), 선반 1~2개, 화분, 유리병/기하 오브젝트,
벽에 걸린 도식 패널(이론 다이어그램이 은은히 빛나는 화면) 2~3개, 스탠드 램프 또는 펜던트 1개.
* 소품은 로우폴리 + 둥근 모서리, 주제와 연결된 것 1~2개 포함. 배경 전체 밝기는 중간(검정이 아닌 따뜻한 갈색/회색).

계측 콘솔 (UI가 세계 안에도 있다)

* 장치는 콘솔 위/안에 놓인다. 콘솔 앞면 구성: 큰 다이얼 1~2개(둥근 노브 + 값만큼 채워지는 발광 원호),
가로형 실시간 그래프 화면 1~2개(캔버스 텍스처, 어두운 화면 + 격자 + 축 라벨 + 발광 곡선 + 현재값 커서),
LED 트랙 물리 슬라이더(크롬 손잡이 + 아래 삼각 마커), 황동 테두리 큰 버튼(재생/일시정지 등),
작품 이름이 새겨진 금속 명판 띠.
* HUD의 값과 콘솔의 다이얼·슬라이더·그래프는 항상 같은 상태를 보여 준다(같은 물리 모듈에서).
* 콘솔 부품도 마우스로 직접 돌리고 끌 수 있다.

조명 레시피

* 따뜻한 키(호박/주황 #ffb36b 계열) vs 차가운 현상광(하늘/청 #7dd3fc 계열)의 보색 대비로 화면 전체를 짠다.
* 화면에 보이는 실용 광원 4개 이상: 전구·램프·LED 띠·발광 화면·다이얼 원호·장치 내부광. 각각 실제 PointLight/RectAreaLight를 동반.
* 앰비언트 오클루전(GTAOPass 또는 SSAO)으로 접촉 그림자. 그림자 맵 1~2개(PCF soft).
* 블룸은 발광 부품과 현상에만(threshold ≈ 0.85, 발광색 ×2~4). 나머지 표면은 무광. ACES 톤매핑, RoomEnvironment 환경맵.
* 가장자리 비네트, 아주 약한 필름 그레인(선택).

재질

* 기계 부품 모서리는 전부 둥글게(RoundedBoxGeometry, 베벨 Extrude, Lathe). 날카로운 CG 박스 금지.
* 팔레트: 짙은 흑연 금속(무광, roughness 0.5~0.7) + 황동/금 포인트(metalness 1, roughness 0.3) + 크롬 + 유리(transmission).
자연물은 플랫 셰이딩 로우폴리.
* 큰 면을 단색으로 비우지 않는다: 패널 이음선, 나사 머리, 통풍 슬릿, 눈금, 각인 텍스트, 고무 패드 같은 미세 디테일.

현상 셰이더 (주인공)

* 주인공 현상은 반드시 전용 ShaderMaterial로: ① 반투명/발광 매질 ② 흐름을 보여 주는 입자(InstancedMesh 또는 Points,
방향 화살표/점 스트릭) ③ 물리량→색 매핑(파장→스펙트럼색, 온도→흑체색, 세기→밝기, 위상→색상환 등).
* 가산 혼합 + 블룸으로 빛나되, 형태가 뭉개지지 않도록 코어는 선명하게.
* 오버레이 토글로 숨은 양(장, 위상, 등고선)을 따로 켜고 끌 수 있다.

HUD 타이포그래피와 레이아웃

* 폰트(Google Fonts): 헤드라인 Outfit 800 / 숫자·라벨 DM Mono(대문자, 자간 .14em, tabular-nums) / 본문 Noto Sans KR.
* 좌상단: 킥커(흰색, 대문자 느낌, 20px) / 헤드라인 동사형 훅(강조색, 52~60px, 줄간격 0.95, 은은한 글로우)
/ 리드 2~3줄(일상 관찰 → 반전 → "이걸 해 보라") / 수치 칩 3개(큰 값 + 작은 보조줄)
/ 캡션 카드(실제 숫자는 색, 핵심어는 굵게, 왼쪽 강조색 테두리) / 필요 시 미니 차트 카드.
* 우상단 유리 패널(반투명 + blur 14px, 둥근 14px): 행1 [시나리오 프리셋 세그먼트 + 연속 슬라이더(값·단위 표시)]
행2 [두 번째 변수 + 오버레이 토글 칩(색점 알약)] 행3 [보기 모드 실험실/분해/스튜디오 + 재생·속도(시간 현상) +
아이콘 버튼: 소리, 가이드 투어, 시네마틱, 도움말]. 각 컨트롤 라벨 오른쪽에 회색 단축키.
* 3D 라벨 알약 5~7개(색점 + 이름 + 실시간 값, 작은 모노 글씨). 겹치면 위치 조정.
* 우하단: 작은 "다른 실험" 카드 자리, 공유 버튼. 하단 중앙: 조작 힌트 한 줄.
* 보기 모드 '스튜디오': 방을 숨기고 장치만 어두운 무한 배경 + 3점 조명으로 보여 준다.
* 모바일(≤980px): 패널은 하단 시트, 세로 화면은 카메라를 시선 방향으로 물려 장치 전체가 들어오게.

글쓰기

* 한국어, 짧고 관찰 가능한 사실. 캡션에는 항상 실제 숫자 2~4개. 조사는 받침 판별 함수로 자동.
* 다른 사이트의 문장·코드·이미지·이름을 가져오지 않는다. 전부 새로 쓴다.

3. 엔진 (고정)
══════════════════════════════════════

* 단일 index.html. Three.js 최신 안정판(r17x 이상)을 importmap(cdn.jsdelivr.net)으로. 빌드 도구 없음.
addons: OrbitControls, RoomEnvironment, EffectComposer, RenderPass, GTAOPass(또는 SAOPass), BokehPass 또는 자체 DoF,
UnrealBloomPass, OutputPass, RoundedBoxGeometry, RectAreaLightUniformsLib, LineSegments2 계열.
* 외부 모델·이미지 0개. 캔버스 텍스처로 화면·눈금·각인·창밖 하늘. 시드 고정 난수(mulberry32). Math.random 금지.
* 규모: 2,500~4,000줄을 허용한다. 짧게 줄이느라 디테일을 빼지 마라.
* 스크립트 섹션 순서: 1 PHYSICS → 2 SCENE/RENDERER → 3 KIT(절차적 부품 함수 라이브러리) → 4 ROOM → 5 CONSOLE
→ 6 HERO APPARATUS → 7 PHENOMENON SHADERS → 8 OVERLAYS → 9 LIGHTS → 10 PIPELINE → 11 CAMERA/SHOTS/TOUR
→ 12 INTERACTION → 13 HUD → 14 LOOP.
* KIT에 먼저 만들 부품 함수(재사용): roundedPanel, bevelFrame, screw, ventSlits, engravedPlate(text), knobWithArc,
ledSlider, graphScreen(drawFn), bigButton, brassTrim, lampWithBulb, ledStrip, glassJar, plant, shelf, windowWithSky,
wallDiagramPanel, rubberFoot. 장면은 이 부품의 조립으로만 만든다.
* state: 변수마다 현재/목표값 쌍, 매 프레임 지수 감쇠. 시간 현상은 t의 순수 함수 + 일시정지·속도(0.25×~2×).
* 렌더 레이어: 방 / 콘솔·장치 / 투명 / 설명 오버레이. 설명 오버레이는 DoF 등 화면 효과 다음에 깊이 테스트하며 합성.
* 장치 단면: 앞/뒤 반쪽으로 나눠 만들고 '분해' 시 앞쪽이 빠지며 투명해지고 내부 부품이 축 방향으로 벌어진다.
* 상호작용: 3D 부품·콘솔 다이얼·슬라이더 직접 드래그, 호버 시 grab 커서. 키: 1~4(프리셋), [ ], 변수 키,
오버레이 키, V(보기 모드), T(투어), C(시네마틱), Space(재생), R(초기화), /(UI 숨김), ?, WASD QE.
* 시네마틱: 샷 6개 순환(7.5초 간격, 3초 부드러운 비행 + 느린 공전).
* 소리(선택, 기본 꺼짐): WebAudio로 다이얼 틱, 버튼 클릭, 현상에 맞는 저음 험.
* 성능: 픽셀 비율 상한 1.6, 2초 평균 프레임이 32ms를 넘으면 AO 끄기 → 픽셀 비율 1 순으로 자동 하향.
* 디버그·검증 훅(필수): 렌더 루프를 frame()(requestAnimationFrame 담당)과 update(dt)(한 프레임 계산+렌더)로 분리하고
window.__lab = { state, set(name, v), preset(i), view(mode), flyTo(shot), SHOTS, tour,
step(n, dt) // rAF 없이 n프레임 진행
shot(i) // 카메라를 샷 i로 즉시 이동
capture(name)// 캔버스 크기가 0이거나 창 크기와 다르면 먼저 리사이즈 → update 1회 → canvas.toDataURL을
 // POST /__save/<name>.jpg 로 보내 shots/에 저장 (창이 숨겨진 채 로드되면 캔버스가 0×0이다) }.
검증 스크립트 한 번은 짧게: step은 120프레임 이하씩 나눠 호출하고, 카메라 후보 탐색은 렌더링 없이 카메라 복제본으로 투영만 계산.
(이유: 브라우저 창이 가려지면 rAF가 멈추고 스크린샷이 예전 프레임으로 남아 검증이 거짓말을 한다.)

구현 함정 (실전 테스트에서 실제로 터진 것들)

* 물리로 위치가 정해지는 물체(움직이는 스크린, 슬라이더 손잡이 등)를 '분해 보기' 위치 복원 목록에 넣지 마라.
복원 코드가 매 프레임 물리 위치를 덮어쓴다. 연출 오프셋은 별도 부모 그룹에 건다.
* 히어로 시점에서 현상(주인공) 앞에 오는 불투명 부품은 현상보다 낮고 좁게 만든다. 카메라는 현상면을 15~30° 위에서 내려다본다.
* 가산 발광 + 블룸은 쉽게 하얗게 포화된다. 상태별로 발광 총량을 정규화하라(예: 빛이 넓게 퍼지는 상태는 이득을 낮춤).
가까이·위에서 찍은 캡처로 포화를 꼭 확인한다. 실험 장치 옆 포인트 라이트는 약하게(강하면 크롬에 하얀 띠).
* 방 소품은 "히어로 카메라가 실제로 보는 벽 띠"에 둔다(3D 좌표를 화면에 투영해 확인).
* 화면 왼쪽 위는 HUD가 덮으므로, 콘솔의 중요한 계측기(그래프·다이얼)는 히어로 화면의 오른쪽 60%에 배치한다.
* 안개 시작 거리는 카메라~뒷벽 거리보다 멀게(안 그러면 뿌옇게 바랜다). 노출 0.8~0.9, 블룸 threshold 0.9 이상에서 시작.
* 화면 수치를 시뮬레이션에서 "측정"한다면 경계 조건을 반드시 처리한다:
① 반복 실행(루프·리셋)은 표본에 실행 번호를 붙여 같은 실행끼리만 비교 ② 0으로 나누기 같은 특이점(충격파, 공명, 임계각)은
숫자 대신 이벤트(효과음·자막)로 바꾸고 무한대·수만 단위 값을 그대로 띄우지 않는다 ③ 아직 데이터가 없으면 기본값이 아닌 "—/무음".
측정값과 공식값을 대표 상태 + 극단 상태(임계 넘김)에서 모두 비교한다.
* 히어로 구도는 렌더링 없이 투영 계산으로 고른다: 카메라 후보 수백 개(거리·방위각·고도·목표점)를 만들어
비교 대상 3개와 장치 끝점이 ① 화면 안 ② 왼쪽 위 HUD 블록 밖 ③ 오른쪽 위 패널 밖에 들어오는 후보 중 가장 크게 잡히는 것을 쓴다.
장치가 가로로 길면 정면 대신 대각선 구도(장치가 화면 안쪽으로 멀어지게)가 대개 해다. 대상은 HUD가 없는 왼쪽 아래 전경에 둘 수 있다.
* 설명용 보조선·원뿔·화살표는 장치(판) 경계 밖으로 나가지 않게 길이를 제한한다.
* 세로(모바일) 화면은 헤더와 하단 패널 사이 빈 띠가 높이 200px 남짓뿐이다. 처음부터 세로 전용 히어로 샷과
접이식 하단 패널(시나리오만 보이고 펼치기)을 설계하고, 같은 투영 탐색으로 검증한다.

4. 제작 순서 (단계마다 스크린샷을 찍어 직접 보고 넘어간다)
══════════════════════════════════════
 1 블록아웃: 회색 박스로 방·콘솔·장치 배치와 히어로 카메라 구도 확정(장치 60~75%, 가장자리 잘림 확인).
 2 조명: 키/보조/실용 광원/AO/블룸. 회색 재질 상태에서도 보색 대비와 깊이가 보여야 다음으로.
 3 재질·디테일: KIT 부품으로 교체, 둥근 모서리와 미세 디테일, 황동 포인트.
 4 현상 셰이더: 주인공 현상과 흐름 입자, 물리량→색 매핑, 오버레이 토글.
 5 콘솔 화면·다이얼: 실시간 그래프, 원호, 슬라이더 연동.
 6 HUD·카피: 헤드라인 훅, 칩, 캡션, 패널, 라벨, 도움말, 투어.
 7 다듬기: 시네마틱 샷, 모바일, 성능, 등장 애니메이션.

5. 비평 루프 (최소 3라운드, 모든 항목 8점 이상까지)
══════════════════════════════════════

* 로컬 서버를 직접 만든다: 정적 파일 제공 + `POST /__save/<name>` 로 받은 data URL을 shots/<name>에 저장하는 기능.
(python이 없으면 PowerShell HttpListener로 serve.ps1. 예약 포트 오류가 나면 다른 포트.)
* 3D 화면 검증은 __lab.step/shot/capture로 shots/*.jpg를 만들어 파일로 열어 본다(브라우저 스크린샷에 의존하지 않는다).
HUD 배치는 브라우저 스크린샷 + getBoundingClientRect로 확인한다.
한 번의 스크립트 실행은 짧게(step 120 이하씩 나눠 호출) — 길면 도구가 타임아웃난다.
* 1440×900, 375×812에서: 히어로 / 프리셋 전부 / 변수 극단값 / 분해 / 스튜디오 / 오버레이 켬 / 위에서 본 현상 /
콘솔 근접 / 도움말 / 투어 2단계. 콘솔 에러 0, 가로 스크롤 0.
* 시각 판정 체크리스트(히어로 샷 기준, 하나라도 아니면 그 문제부터 고친다):
□ 장치가 화면의 60% 이상 □ 프레임에서 잘리는 물체 2개 이상 □ 보이는 실용 광원 4개 이상
□ 따뜻한/차가운 보색 대비가 보인다 □ 배경에 흐린 소품 5개 이상, 검은 허공 없음
□ 단색으로 빈 큰 면 없음(디테일 있음) □ 콘솔 화면에 움직이는 그래프 □ 다이얼 원호가 값과 일치
□ 현상이 전용 셰이더로 빛나고 흐름 입자가 있다 □ 헤드라인이 동사형 훅이다 □ 캡션에 실제 숫자 2개 이상

□ 비교 대상 3개가 모두 히어로 화면 안, HUD 밖에 있다(투영 좌표로 확인) □ 극단 상태에서도 화면 숫자가 말이 된다(∞·수만 단위 없음)

한 단계에는 하나의 의미 있는 행동을 배치한다.
사용자가 장비·표본·조건을 직접 조작하고, 그 행동이 물리 모듈의
변수나 경계 조건을 실제로 바꾸도록 연결한다.
단계 수는 학습에 필요한 만큼 정하며, 의미 없는 조작을 추가하지 않는다.

조작 전에는 목적을, 조작 후에는 바뀐 값과 이유를 쉽게 설명한다.
최종 실행은 사용자가 만든 조건을 유지한다.

시간 변화가 핵심이면 재생한다.
정적 관계가 핵심이면 계산·비교·공간 탐색을 실행한다.
확률이 핵심이면 반복 시행과 분포를 관찰하게 한다.
이론에 없는 반복 주기나 흐름 입자를 억지로 만들지 않는다.

결과와 완료 조건은 해당 이론의 모델과 관찰 증거에서 결정한다.
설명용 비유·과장·근사는 명시하고 실제 현상과 구별한다.
