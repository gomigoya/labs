# 기획: 글 없이 읽히는 과학 실험실 (마스터 프롬프트 개정)

## 목표

글을 전혀 모르는 사람도 **조작만으로** 물리 원리를 파악하는 실험실을 만든다.
- 학생은 직접 조작하고 퀘스트를 진행하며 원리를 알아 간다.
- 교사는 같은 실험실을 조작하며 아이들 앞에서 원리를 설명한다.
- 프롬프트는 어떤 과학 이론에도 넣을 수 있는 범용이어야 한다.
- 결과물은 과학관에 바로 전시할 수 있는 시각 품질이어야 한다.

## 1. 진단: 지금 프롬프트가 글을 만들어 내는 지점

| 위치 | 지시 | 결과 |
|---|---|---|
| 1-g | 이야기형 프리셋 "이름" | 버튼마다 문장 |
| 1-i | 수치 칩 3개 (큰 값 + 보조줄) | 숫자·단위·설명 줄 |
| 1-l | 캡션 상태기계 (숫자가 든 완결 문장) | 화면에 항상 문장 |
| 1-m | 가이드 투어 5~7단계 | 설명 문단 |
| 1-o | 헤드라인 (킥커 + 동사형 훅) | 큰 제목 글자 |
| 2 HUD | 킥커, 52~60px 헤드라인, 리드 2~3줄, 칩, 캡션 카드, 패널 라벨 + 단축키, 3D 라벨 알약(이름 + 값), 조작 힌트 한 줄 | 화면의 20~30%가 글 |
| 2 글쓰기 | "캡션에는 항상 실제 숫자 2~4개" | 숫자로 이해시키려 함 |
| 5 체크리스트 | "헤드라인이 동사형 훅", "캡션에 실제 숫자 2개 이상", 점수 ②첫 화면 훅 ⑫투어 | 평가가 글을 요구 |
| 퀘스트 부록 | "조작 전 목적, 조작 후 바뀐 값과 이유를 쉽게 설명" | 설명 글 |
| 사이트 추가 규칙 §3 | 모든 HUD 문장을 ko/en 사전에 | 문장이 있다는 전제 |

**빠진 것**
- 학생용·교사용 두 사용 방식
- 글 없는 퀘스트 흐름: 목표를 어떻게 알리고, 예상을 어떻게 받고, 결과를 어떻게 확인시키는지
- 원리를 모양으로 전달하는 시각 문법
- 전시 운영: 대기 화면, 무조작 초기화, 터치 우선
- 삽화·캐릭터 금지

## 2. 방향

1. **'글자 0' 규칙을 정의하고 자동으로 검사한다.** 기본 화면에 단어가 0개여야 한다.
   - 허용하는 것: 기구에 새겨진 눈금 숫자, 아이콘, 색, 모양.
   - 숫자와 단위는 교사의 '수치 층'(기본 꺼짐)에서만 보인다.
   - 이해가 숫자를 읽는 데 기대면 안 된다. 크기는 마디·길이·개수로 셀 수 있게 한다.
2. **글이 하던 일을 시각 문법이 맡는다.** 원리 유형마다 표현을 하나씩 정해 범용 사전을 만든다.
   - 크기는 마디로, 비교는 겹쳐서 보여 준다.
   - 합과 보존은 쌓아서 채우고, 비례는 같은 간격의 계단으로 보여 준다.
   - 문턱은 한계 윤곽과 그것을 넘는 사건으로, 시간은 같은 간격의 흔적으로 보여 준다.
   - 확률은 쌓이는 분포로, 숨은 구조는 돋보기 단면으로 보여 준다.
3. **글 없는 퀘스트 6단계**
   - ① 장면 제시: 대상이 빛난다.
   - ② 예상: 같은 시뮬레이션으로 돌린 결과 후보 그림 중 하나를 고른다.
   - ③ 조작: 유령 손이 한 번 시범을 보이고, 목표 윤곽이 뜬다.
   - ④ 관찰: 결정적 순간에 연출이 붙는다.
   - ⑤ 확인: 고른 그림을 실제 결과와 겹쳐 본다.
   - ⑥ 원리 카드: 그림 등식을 받는다.
4. **두 모드는 같은 장면을 쓰고 도구만 다르다.**
   - 학생 '탐험': 퀘스트 진행과 자유 실험.
   - 교사 '시연': 투사용으로 크게 띄우고 다음 도구를 쓴다.
     - 정지·슬로
     - 표현 층을 하나씩 켜기
     - A/B 고정 비교
     - 스포트라이트
     - 수치 층
     - 퀘스트 바로가기
     - 학급 예상 화면
   - 설명 글은 화면 밖 '교사 안내서'(guide.html)로 옮긴다.
5. **말소리 해설은 넣지 않는다.** 효과음과 소리화(음높이 = 크기)만 쓰고, 소리를 꺼도 이해되게 한다. 언어 중립이라 어느 나라 전시관에서도 그대로 쓸 수 있다.
6. **전시 품질 기준을 추가한다.**
   - 지금 아트 디렉션(방·콘솔·조명·재질·현상 셰이더)은 유지한다.
   - HUD는 '아이콘 전시 UI'로 바꾼다. 화면 위의 퀘스트 띠와 아래의 도구대 두 곳만 두고, 나머지 조작은 장면 속 손잡이로 한다.
   - 대기 화면, 터치 타깃 56px 이상, 무조작 초기화, 색각 이상 대비 이중 부호화를 넣는다.
7. **금지 목록**: 삽화, 캐릭터·마스코트, AI 생성 이미지, 클립아트, 이모지. 장면 속 명판·화면에도 글자를 쓰지 않는다.
8. **검증을 바꾼다.**
   - '글자 검사' 스크립트로 기본 화면의 단어 수를 0으로 확인한다.
   - '글 가리고 5초' 테스트: 퀘스트마다 소리를 끈 스크린샷 2장(전·후)만 보고 원리를 말할 수 있는지 본다.
   - 점수표의 '헤드라인·투어'를 '무글자 이해·퀘스트 흐름·교사 시연'으로 바꾼다.

## 4. 근거 (forces 실험실을 실제로 써 보며 얻은 것)

- **생성 삽화는 실험실의 격을 떨어뜨린다.** 생성 그림은 모두 걷어내고, 보이지 않는 것은 코드로 그린 단면 도해로 보여 준다.
- **조작은 장면 속 손잡이로 한다.** 고르기·개수 조절은 화면 아래 고정 도구대에 두면, 누르는 동안 버튼이 움직이지 않고 장치를 가리지 않는다.
- **조건을 바꿔도 초기화하지 않는다.** 마우스 한 손으로 양쪽 힘을 맞추려면 고정 핀이 필요하다.
- **연출은 과학적 사건에만 쓴다.** 슬로 모션, 해설은 한 번에 하나만, 결정적 순간에는 UI를 비운다.
- **힘 마디, 한계 윤곽, 직전 값 윤곽, 시간 기록 점, 늘어남 계단, 부력 이어 붙이기**는 글 없이 원리를 전달하는 데 효과가 컸다.
- **검증에서 생긴 문제**: 창이 가려지면 rAF가 멈추고 스크린샷이 예전 프레임으로 남는다. 3D 확인은 캡처 파일로 한다.
